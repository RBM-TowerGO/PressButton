# 定位、纠偏阶段与无效微调修复

本次针对 `20261102_002849_b03f7d26` 的问题修改默认 grounded 流程。只运行代码测试和保存图片的模型回放，没有连接机器人或执行回放建议。

## 原问题与修复

1. 第 6 轮，原判读将头图中位于手指上方的按钮写成 `below`；动作理由中的 `button is right of the right finger and below it` 又被文字校验器误解析为以 finger 为主语。修复嵌套宾语误报，并将当前判读升级为定位输出：模型提供按钮框和所选指尖，程序计算左右、上下及相对于按钮宽高的偏差。坐标计算可避免文字方向翻转，但不能保证模型定位正确。
2. 原判读只有粗略方向，动作 Agent 缺少偏差大小和明确的处理顺序。现在每轮生成 `control_plan.json`，区分获取视角、纠偏、复核、接近、撤回和完成；已知偏差优先处理较大轴。5/10/20 mm 只是小/中/大偏差的可调整试探建议，不是标定补偿或执行限制。
3. 重复请求绝对头部角 `[0,30]` 不会再低头 30°。现在输入包含上次实际发送目标、当时及当前实测角；在视野不足且实测头姿未明显变化时，重复相同目标会进入一次格式/决策修正机会。仍由模型选择新目标，不由程序增加角度。
4. “纠正横向/高度偏差”的目的必须对应 Y/Z 动作且 X=0，避免把前推进藏在纠偏描述中。原始数值不会被裁剪或替换；明确选择接近/按压时，正 X 继续走既有腕图横向检查。
5. 保留旧统计归档，但模型输入只保留新的当前阶段优先级，避免旧的“长期未处理轴”和新的“较大偏差轴”给出相反指令。

## 保留的行为

- 默认头图右侧手指，允许张开夹爪、单边按压；未知手指位置保持未知。
- 用户选择的前推条件仍是**仅检查当前腕图横向是否位于两指之间**。没有新增高度、有效深度或闭爪门槛。此条件不能保证能按到按钮正面。
- 保持共享执行器、HTTP 动作格式、坐标、插值、速度、一次在途命令、幂等与停止处理。发送完成不代表到位、接触或任务成功。
- 判读默认 2 张当前原图；动作默认 3 张成功拼图加 2 张当前原图。正 X 候选仍另需一次独立腕图检查。
- 网页展示定位偏差、阶段、建议主轴和步长，以及判读对应观测 ID。它们是模型定位及程序建议，不是人工确认或毫米测量。
