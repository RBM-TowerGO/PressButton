# 白箭头 direct：进展监测与异常复核

本次实现不启动真机。只使用保存图片调用 qwen38，以及 fake SDK/HTTP 自动化回归。原始运行、请求和图片没有改写。模型建议均未发送给机器人。

## 已实现的行为

- 原 direct 启动命令自动启用进展监测。正常一轮仍是一次动作模型请求；已有正 X 横向前推检查独立保留。
- 每次工具调用增加结构化 `progress`：当前观测 ID、子目标、使用视角、按钮相对接触指端的上下/左右关系、上一步效果。它是模型判断，不能当作测量真值。共享执行器收到的仍是原始 XYZ、头部角度或 c/o 参数，`progress` 不发送到机器人接口。
- 程序只计实际完成发送的运动，连续三次同方向平移触发复核；模型报告无改善、恶化、越过或未知，或者已经同高/同列、关系反转却仍重复该轴时，也会触发复核。重复本身不等于失败。
- 复核独立接收最近实际运动前与当前的头部/腕部原图，共四图，以及实际命令。没有示范、旧动作理由、旧判读或待执行候选。头部/夹爪操作结束原来的可比较区间。
- 复核必须支持仍有改善，才允许继续上次同轴同方向；同高/同列、越过、恶化、无改善或未知不能支持继续该方向。没有自动反向、固定补偿、裁剪、拆分或替代动作。
- 候选被拒后使用原有的一次修正机会。模型再给非法/不支持的候选则结束。复核传输失败或格式修正一次仍非法，也结束，不绕过复核。
- 单纯重新观察和零位移不能清除尚未解决的复核状态；新观测仍需新复核，不复用旧观测的许可。q/Ctrl-C、迟到响应、单动作在途和执行幂等语义保持。
- 压缩保留动作台账中的进展/复核及最近五轮；网页区分程序命令统计和模型判读，显示复核阶段、观测 ID、图片数、token、耗时及错误。

白箭头提示词使用箭头指向的**物理指端**，不使用整张贴纸中心、不把箭头方向当运动方向、不声称接触点已标定。先获得可用头部视野；约 30°只是绝对俯仰参考。按钮通常较高的先验只用于首次高度判断，不能覆盖实时变化。

**结论：流程能阻止不受复核支持的重复运动，但尚未证明模型能够正确对齐并恢复任务。旧红标记复核仍有误判，不能把“拒绝继续抬高”算作视觉正确或任务成功。白箭头只验证了初始取景决策，尚无白箭头运动前后序列来验证进展判断。**

图像中的同高仅是二维投影关系，不是物理接触或正 X 放行证据。上述人工看图结论是本次文档复核，不是现场操作员成功确认。

## 验证及启动

相关自动化回归最终472项通过、1项跳过（环境无Node）；网页脚本另用V8实际渲染验证通过。包含新增失败案例读取兼容检查，详细结果见 `checks.json` 和 `regression.xml`。测试覆盖真实完成事件计数、重复命令ID、四图及观测绑定、一次修正、取消/迟到响应、压缩、刷新和零位移不能绕过、共享执行器与原有前推检查。

启动方式不变：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_run.py \
  --decision-mode direct --demo-last-steps 3 --no-failure-case \
  --prompt docs/astribot/planar_control/agent_system_prompt_red_marker.txt
```

原文件名保留兼容，内容现为白箭头。网页 <http://127.0.0.1:8766> 显示画面、动作理由、进展和复核。修改在下次启动时加载。

仅模型复现：

```bash
.conda/envs/pressb/bin/python scripts/validate_agent_progress.py --output outputs/progress_model_replay
```

需要只检查已保存的白箭头初始画面时增加 `--arrow-only`。输出目录必须不存在。脚本只建立模型隧道，不构造机器人客户端。
