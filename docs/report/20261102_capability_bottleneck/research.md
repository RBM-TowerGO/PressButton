# 能力瓶颈分析：公开资料能支持什么

日期：2026-11-02。本文件核对已有研究记录及六个相关的一手来源，不调用模型或机器人。项目内对照实验比公开榜单更直接地回答本任务瓶颈；公开资料用于解释能力差异和界定归因范围。

## 本机模型与编码能力的适用范围

`qwen38` 是服务别名，项目实际使用 `Inferact/Qwen3.8-27B-NVFP4`。该仓库明确是 `Qwen/Qwen3.8-27B` 的量化版本，模型卡没有报告本机按键任务成绩。不能把其他规模或托管型号的表现代入本服务。[Inferact 模型卡](https://huggingface.co/Inferact/Qwen3.8-27B-NVFP4)

Qwen 官方将27B定义为原生视觉语言模型，同时分别报告编码、视觉问答及具身推理成绩；例如SWE-bench Pro为61.7，LiveCodeBench v6为90.3，ERQA为65.5。这些分别衡量不同任务，数字之间不构成同一能力的换算，也不是当前NVFP4部署的本地复测结果。[Qwen3.8-27B 官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)

ERQA官方定义是400道图文多模态选择题，输出A/B/C/D。它考查具身相关推理，但不让模型驱动这台机器人，也不验证毫米位移、接触和多轮纠偏。用ERQA成绩推断本任务成功率没有依据。[ERQA 官方代码与数据说明](https://github.com/embodiedreasoning/ERQA)

## “人觉得简单”不等于模型擅长的输入与运算

《Vision language models are blind》最新版研究了交叉线、重叠圆等基础视觉任务。研究发现所测模型在精确几何关系上仍会出错；其线性探针实验还发现视觉编码器含有足够信息，后续语言模型却未稳定转成正确答案。该结果支持区分“像素进入模型”和“模型能正确报告局部关系”。研究对象及任务不是本次Qwen部署，不能据此断定我们的错误必定发生在语言层或某个具体模块。[论文，2025年修订版](https://arxiv.org/abs/2407.06581)

SpatialVLM把通用视觉问答与定量3D空间推理分开研究，并提出空间训练数据不足的假设；通过专门构造的空间问答数据提升了所测模型的定性和定量空间推理。它支持将空间能力单独测试，不能证明Qwen3.8训练中夹爪很少，更不能把我们尚未隔离的二维识别问题直接叫作3D推理失败。[SpatialVLM，CVPR 2024](https://spatial-vlm.github.io/)

## 量化是候选因素，不是已有结论

NVIDIA说明PTQ后的精度变化取决于模型和量化方法。因此需要同一基础模型、同一图片／提示／采样设置下的高精度与NVFP4对照，才能评估本任务的量化损失。[NVIDIA Model Optimizer PTQ说明](https://github.com/NVIDIA/Model-Optimizer/blob/main/examples/hf_ptq/README.md)

项目此前的[实际服务审查](../20261101_panel_shift_root_cause/model_service_audit.json)显示量化忽略列表包含`model.visual*`。这不支持“视觉塔也统一变成4bit”的说法；但也不意味着经过量化的语言侧一定不影响视觉答案。当前没有受控精度版本对照，应保留未知。

## 对这次实验解释的约束

| 可以支持的判断 | 尚不能支持的判断 |
|---|---|
| 编码与本机视觉闭环应分别验证 | 编码强所以必然会控制此夹爪 |
| 原图输入、对象定位、二维关系、动作映射应分开测 | 漏认白箭头就证明没有图像输入 |
| 给出正确位置后再测试关系，可隔离部分上游识别错误 | 任意一次错误方向都代表不会空间推理 |
| 以固定图像和人工给定事实对比动作，可以检查事实到动作的能力 | oracle条件正确就证明已具备真实机器人操作能力 |
| 比较高精度与量化版本才能测量量化影响 | 没做对照就把失败归咎于NVFP4 |
| 根据本项目对照结果讨论输入组织和模型先验 | 未公开的训练集里“肯定缺夹爪” |

面向用户的解释宜表述为：这个任务同时要求从陌生、部分遮挡的图像中找到特定物理接触端，比较局部关系，再将它转换到本机坐标并依据真实反馈修正；公开编码成绩不能替代这些环节的测量。是否真正存在二维关系、机器人坐标或闭环学习瓶颈，仍应由本次分层实验确定。
