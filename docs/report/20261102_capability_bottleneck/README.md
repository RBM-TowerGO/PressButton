# Qwen 当前按键任务的能力瓶颈：已有对照与16次分层检查

日期：2026-11-02。对象为现有 `qwen38` 服务，即 `Inferact/Qwen3.8-27B-NVFP4`。本次只读取实验记录，并对保存图片发送16次模型请求；没有连接机器人执行动作，没有修改生产提示词、门控或共享执行器。

**可以把问题缩小到功能环节，但不能仅凭输出确定神经网络内部是哪一层失效。当前最强证据指向：从画面稳定提取“正确目标相对正确接触参考”的二维状态不可靠；此外，正确状态进入动作会话后也可能被忽略。没有证据支持“模型完全不懂上下左右或XYZ正负号”。真实三维几何和毫米控制尚未被这些实验验证。**

## 1. 为什么这次要分层检查

完整任务包含以下不同问题：

1. 找到要按的按钮和指定接触手指，而不是另一根手指、螺丝或按钮上的三角。
2. 将按钮与正确参照绑定，判断它们在同一画面的上下／左右及可见性。
3. 结合相机安装、机体姿态、接触点和距离，把图像偏差转换为机器人方向及毫米位移。
4. 根据当前证据选择动作，执行后检查变化，放弃已经失效的判断。

模型在第1或第2步写错了当前状态，后续理由即使流畅、XYZ格式即使正确，仍会执行错误策略。反过来，判断出图中左右也不能证明已经掌握第3步的三维控制。

## 2. 新实验设计

选取两幅真实白箭头腕图：

- A：运行 `20261102_120741_0ca36af5` 第8轮。助手检查按钮中心约(420,117)，箭头所指物理前端约(470,280)。按钮明显在上方、略偏左。
- B：运行 `20261102_142505_13668097` 第5轮。按钮约(164,60)，指端约(470,280)。按钮明显在上方、较大幅度偏左。

点位为助手对保存图的近似标注，不是现场人员新增确认或接触点标定。像素偏差远大于几像素的标注不确定性，因此足以检查粗上下左右；不能用它验证接触精度。

所有条件在调用前固定于 [plan.json](probes/plan.json)。原图条件不提供坐标或正确方向，只让模型报告可见性及目标相对参照的上下左右；没有示范、历史理由、深度、动作选择或机器人接口。分别测试贴纸整体与所指物理前端，再测试局部裁剪放大、T/P标点和纯数值坐标。A/B物理前端原图请求各原样重复一次，没有挑选最好结果。模型参数为temperature=0、thinking关闭、max_tokens=256，不做格式修正。

## 4. 最明确的瓶颈与边界

### 图像到可用位置关系：已观察到不可靠

A的原图请求只有约748输入token、1张图、4个字段，仍连续两次判错左右。因此长历史、大量示范或64K压缩不是发生这类错误的必要条件。A裁剪后正确、B原图正确，也说明失败依赖画面及呈现方式，不能说模型在所有画面上都不能识别夹爪或空间关系。

A中目标到物理端的水平差约50像素，B约306像素。现有结果与“小偏差更难稳定判断”的解释相容，但只有两幅图，不能据此发明一个可用像素阈值。裁剪同时改变了物体尺度、背景范围和干扰物，不能唯一归因于图像分辨率。

“模型说两个对象可见”没有验证它实际选中了哪两个对象。自然图不输出位置，标T/P图也没有验证模型正确读出标签，因此还不能把错误唯一定位到对象检测、参照绑定或视觉关系解码中的某一个。**当前能确定的是这个组合环节不可靠；不是已经证明模型拿到了正确点坐标后仍不会比较。** 纯坐标4/4正确恰好支持后一区分。

与此前三帧详细定位结果相比，本次最小问题在B上可回答正确，而详细判读给出partial／unknown。输出任务及输入组织会改变表现，但两组提示、图数、schema均不同，不能把差异仅归因于某一个字段。

### 当前状态约束动作：已有独立失败证据

此前3个相邻偏移帧中，保留原请求、只追加坐标说明、只补工具坐标描述，均持续前推。仅追加经图像审查的可见性、相对位置和未对齐状态，不告诉模型机器人轴或毫米，它就3/3改为-Y10。[原始对照](../20261101_action_interface_mapping_audit/README.md)

这说明正确视觉中间状态可以改变动作选择，瓶颈不只是正负号。但另一组长历史请求即使收到正确的4个粗视觉字段，仍重新声称腕图按钮位于两指之间并给出不相符动作。因此“增加一个判读Agent”并不保证其结论会被动作Agent可靠消费。[历史及判读对照](../20261101_panel_shift_root_cause/README.md)

该现象可以描述为当前证据没有稳定约束决策；它不证明模型内部必定先决定动作再编造理由，也不能唯一归因于某种注意力机制。

### 已知机器人方向到XYZ：已有可完成证据

此前纯文本六方向请求6/6正确，包括机器人右→-Y、上→+Z。因此不能将持续前推概括成“模型不知道右是-Y”。但语义不清楚的`next_axis`字段确实曾产生符号冲突，补明它指的是手的期望运动而不是物体图像运动后可纠正。这说明接口语义仍重要，不能仅靠一个字段名表达约定。[方向接口检查](../20261101_action_interface_mapping_audit/README.md)

### 图像到机体几何、毫米和接触：仍未验证

像素左右不是任意姿态下的机体左右。当前输入没有完整相机到机体变换、已标定手指接触点或经过验证的局部图像误差到毫米映射。同一个投影误差可能对应不同三维距离和运动组合，固定点深度也不是按钮接触点深度。

本次纯坐标正确和旧oracle条件-Y正确，都没有验证毫米幅度、实际接触或按键成功。缺少几何映射是后续定量控制问题，但不能拿它解释已经观测到的清楚二维左右判错。

## 5. 最新死循环不能单独当作模型能力测验

最新连续低头同时受四个系统问题影响：HEAD必须精确识别小箭头物理端的门槛过强；get_view没有自身进展检查；头部实测长期落后目标；任务字典并发复制异常导致HTTP503。这些不是纯模型能力变量。[最新运行审查](../20261102_view_loop_audit/README.md)

因此，不能用这次五轮低头推出“模型完全不会机器人控制”。程序当时移除了所有手部工具，模型连提出手部纠偏的接口都没有。模型本可报告无法继续却选择持续低头，这属于策略与阶段可达性问题，仍需与程序限制一起分析。

## 6. 为什么编码强不能直接推到按按钮

许多编码任务的状态由文件、变量和明确接口构成，模型可以直接处理这些文本符号。当前机器人任务首先要从像素中生成状态变量：“哪一个才是接触端”“按钮相对它在哪边”。一旦这一步填错，后续推理和合法工具调用都可能围绕错误状态展开。这是本项目观察到的能力不均衡，不是对模型整体智力的评分。

Qwen官方分别列出编码与视觉／具身问答指标；其中ERQA是400道图文多选题，不能换算成此机器人毫米闭环成功率。[官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)、[ERQA定义](https://github.com/embodiedreasoning/ERQA)。基础视觉关系任务中出现明显错误也有公开研究，但那些模型与任务不同，不能据此断言本次Qwen具体某一网络层出了问题。[BlindTest论文](https://arxiv.org/abs/2407.06581)

本机实际使用27B的NVFP4部署，不是其他规模或托管型号。本次没有同帧、同提示的高精度权重对照，不能把失败定因于量化；也没有训练集证据支持“夹爪见得少”这一具体解释。公开资料和这些归因限制见 [研究说明](research.md)。

## 7. 对下一步的含义

优先目标应是让当前状态有可检验的视觉依据，并把未知与错误分开：保留全局取景，同时对按钮／所选接触端使用可检查的局部视图或定位；先验证这一环节，再讨论毫米控制。裁剪这次有改善，但不能用当前两个样本自动确定裁剪策略或承诺稳定成功。

动作层需要检查当前视觉证据与选定动作是否一致，防止较早的“已对齐”描述继续控制当前动作。取景阶段与执行反馈问题也要独立修复。Thinking在此前三帧配对实验中没有纠正持续前推，说明该配置下多生成推理并不自动修复错误视觉状态；不代表所有thinking条件均无用。[已有thinking对照](../20261101_direct_thinking/README.md)

若进一步要求定位到底是尺度、参照绑定还是模型精度导致，可以另做严格保持其他因素不变的全图尺度／局部范围对照及同基础模型精度对照；本次不将这些未做的实验写成结论，也不自动启动真机。
