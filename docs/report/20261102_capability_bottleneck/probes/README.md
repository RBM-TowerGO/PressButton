# 保存腕图的分层能力探针

本次共16次独立、仅模型请求，全部连接现有`qwen38`，未构造机器人客户端、未发送运动命令、未修改生产提示词或控制代码。`temperature=0`、thinking关闭、`max_tokens=256`。所有条件、近似标注点和预期二维关系在首次请求前保存于[plan.json](plan.json)；只记录首次响应，没有格式修正或挑选最好答案。

## 输入与判定范围

- A：`20261102_120741_0ca36af5`第8轮腕图，观测`f31cc38545bf422b980a9196c7a4ebbd`。助手预先查看原图后标注按钮中心约`T=(420,117)`、箭头所指物理前端约`P=(470,280)`，贴纸整体中心约`(509,315)`。
- B：`20261102_142505_13668097`第5轮腕图，观测`981630409f1349a2a93a53a23eb19399`。对应约`T=(164,60)`、`P=(470,280)`，贴纸中心约`(509,315)`。

这些是助手对保存图片的二维近似标注，不是现场人员确认、接触点标定或机器人坐标。两幅图的按钮都明显在标记／所指指端上方偏左，关系间隔大于几像素标注误差。A的按钮—指端横向间隔约50像素，B约306像素；两图均640×360。

原图条件不输入这些点坐标或正确关系；模型只看图片和目标／参照说明。`sticker`指定整块白箭头贴纸中心，`tip`指定箭头所指的物理手指前端。标T/P条件则问人工标注点之间的关系，不再要求模型自行选择物理接触端。纯文字条件只比较已给定的二维数字点。

## 可以支持的结论

1. **不能把问题说成模型完全不会上下左右概念。** 在明确给定二维坐标及x向右、y向下约定后，四种组合4/4正确。B的原图关系也正确。但这没有验证相机到机体变换、三维接触或毫米步长。
2. **视觉输入到指定参照的关系提取有明确不稳定性。** A在只有一张图、没有示范／动作历史、只有四个简短字段的情况下仍把左右判反，重复相同请求保持错误。因此长上下文和复杂输出schema不是这些错误的唯一条件。
3. **改写“贴纸”或“物理指端”不足以单独修复A。** 两种指代在A都错、在B都对。这不支持仅凭当前数据断言“模型只是不了解夹爪这个词”。也不能由此排除指代和参照选择问题。
4. **视觉呈现方式会影响结果。** A裁剪并放大后关系正确，说明该帧不是模型必然无法回答。但该操作同时扩大局部、改变目标间隔占画面比例并移除背景／其他手指，无法单独归因于分辨率、干扰物或注意力。
5. **人工加T/P小标签也不保证可靠。** 两项仅1项正确，原图甚至完全反向。小标签阅读、T/P角色绑定或空间关系提取都可能参与；不能声称已确认模型正确识别了两个标注点之后仍然算错。

综合这些条件，最有证据的薄弱环节是**从原图稳定选中指定视觉实体、绑定目标与参照，并输出可信的局部二维关系**。当前实验仍无法把对象定位错误、参照绑定错误、视觉关系解码错误唯一分开；应保留这一定位边界，不直接归咎某个神经网络层或训练数据缺少夹爪。

## 实验限制及一项设计混杂

- 仅两幅困难腕图，各条件一次，只有两项精确重复。总计“10/16关系正确”混合了不同任务和人为控制，不是总体准确率，不应当作真实机器人成功率。
- 上下翻转是离线诊断刺激，未写入任何真机观测。它也翻转了按钮内部向下三角，而原图提示仍称`DOWN-CALL`，且夹爪倒置。这给两项raw翻转条件引入目标语义和分布变化，**不能用其失败证明模型不能比较上下**。结果原样保留，没有事后修改问题重测凑正确。
- 标T/P条件不含按钮语义，避开上述翻转符号混杂，但引入小标签识别与人为显著性变化，仍不是无歧义的内部机制探针。[标注原图](figures/A_raw_marked.jpg)、[标注翻转图](figures/A_flip_marked.jpg)。
- 纯文本点坐标题使用仅两关系字段schema，避免无图情况下“可见性”字段歧义。它与图像题任务不同，只证明给定数字后的比较能力。
- 裁剪原图同时改变上下文及像素尺度；标注位置未经物理标定，模型输出亦未执行。没有做量化、高精度权重、thinking或其他模型的对照。

## 可追溯性

[quality_checks.json](quality_checks.json)核对原始图片未修改、精确重复请求相同、实际thinking关闭和语义一致性。全部可读请求以图片哈希文件引用保存，发送前恢复后与真实payload逐项相等；图像保存在`images/`，独立观测来源和脚本哈希在[source_hashes.json](source_hashes.json)。当前服务信息在[models.json](models.json)。运行时脚本副本为[script_used.py](script_used.py)。

```bash
.conda/envs/pressb/bin/python scripts/diagnose_agent_capability.py \
  --output outputs/capability_probe_new
```

输出目录必须不存在。脚本只调用模型的`/models`和`/chat/completions`，无运动接口。
