TASK AND REFERENCE
Press the elevator down-call button using the physical finger front end indicated
by the WHITE/CREAM ARROW. Observe this run's target indicator turn on, then withdraw
and obtain visual withdrawal evidence. The arrow identifies the physical front
end, not the sticker center. Its drawing direction is not a robot motion direction
and the marker is not a calibrated contact point. Do not substitute the other

identity remains unknown unless the marker and physical end are identifiable.

CURRENT EVIDENCE
Each current observation has independent model localizations and program-derived
image relations. Read the current effective localization revision before choosing
an action. Boxes and points are MODEL ESTIMATES; program arithmetic does not make
them human-confirmed measurements. The program calculates button center minus
the marked contact end separately in HEAD and WRIST: image x increases right and
y increases down. Negative dx means the button is image-left of that end; negative
dy means image-above. Near center/level is only a 2D projection relation, not
physical contact, activation, or permission to push. Pixels and button-size units
are not millimeters. Do not invent a camera-to-chassis transform or compensation.

Use the observation ID, localization revision and view requested by visual_basis.
Use only a currently usable view for hand adjustment; do not copy historical coordinates or combine
a HEAD button with a WRIST fingertip. You do not independently fill in relation
or improvement fields. If the locations appear wrong, cite the specific current
image evidence in the short reason and request a new observation or improve the
view. Do not silently replace a program relation with an old narrative.

VIEW AND PROGRESS
Either HEAD or WRIST can support adjustment when the target and marked physical
end are both located there. An incomplete HEAD view does not invalidate a usable
WRIST view. When neither view is usable, choose head adjustment, observation or
report_unable. An evidence-backed report_done remains available when this run's
activation and later withdrawal can be verified; retreat may remove the target
from the current image. About +30 degrees absolute head pitch
is an initial look-down reference, not a required startup motion, increment or
angle to repeat. Keep an adequate view; if a prior target did not improve framing,
check measured head angles and choose a supported different view or report unable.
Head motion does not move the hand or wrist camera.

Program progress uses recorded motion and before/current locations. It describes
changes in image error, not measured 3D alignment. Observe the result of each
command. If alignment error stalls, worsens, crosses its image target or becomes
uncertain, reassess the subgoal rather than repeating an unsupported direction.
An independent localization review may invalidate one view while another remains
usable. A conflict cannot be resolved merely by restating agreement on the same
image; request fresh evidence. Never automatically reverse an axis based on a
disputed point. Forward X motion need not reduce a 2D alignment offset.
WRIST moves with the hand, so the marked end can stay fixed while the button moves.
Changed camera pose, gripper shape, target identity or scale can make comparisons
unknown. A sent command is not proof that the hand arrived or improved alignment.

COMMANDS
Choose one command. Move [X,Y,Z] is an incremental chassis displacement in mm,
added to the previous commanded target with orientation preserved: +X forward,
-X withdraw, +Y robot LEFT, -Y robot RIGHT, +Z up, -Z down. Image directions are
not automatically chassis directions. Head [yaw,pitch] is absolute degrees.
c closes and o opens; startup preserves the opening. Open single-finger pressing
is allowed. Aim at the pressable face, not its rim. There is no automatic closure,
press-and-return, fixed step schedule, fixed X plane, or depth-minus offset.
Numeric command parameters remain the Agent's choice and are not clipped.

FORWARD AND COMPLETION
Every positive X candidate, including XYZ combinations, must pass the independent
CURRENT WRIST check. The program compares the located button center with BOTH
visible finger front ends horizontally. The inner boundary permits single-finger
pressing. Unknown or outside fails: that candidate was not executed. Choose a
supported non-forward action, improve the view, observe or report unable.
This is only a horizontal condition: no extra height, depth or closed-gripper gate.
Invalid fixed-point depth or unconfirmed activation alone does not prohibit a
forward proposal. Passing the check does not establish 3D contact or task success.

Report completion only with THIS RUN's light-on observation and subsequent visual
withdrawal evidence IDs. The evidence text must contain exactly these two observation
IDs, in light-on then withdrawal order; the program separately checks the earlier
off-to-on transition and later withdrawal images. A historical lit button, single unverified lamp state,
reflection, small depth, contact-like overlap or completed send is not proof.
Do not invent missing evidence. Model judgments and human outcome records differ.
