日期：2026-11-02。新默认流程为 `localized`，保留旧 `direct`、`separated`、`grounded` 模式。本次没有启动机器人，没有执行任何新建议。

## 本次接线

当前双图独立定位 → 程序按各自相机坐标计算关系与进展 → 持续会话中的动作 Agent → 原共享执行器。动作数值仍由 Agent 选择，没有像素到毫米转换、固定步长或自动反向。

- `localized` 成为两种入口默认值；默认成功尾三步、不加载失败案例。显式模式、案例和提示词参数继续优先，旧模式保留。
- 模型定位按钮框、箭头框、物理指端和可见性；程序计算偏差，按当前观测与版本绑定动作。头图或腕图任一有效即可继续，双图均无效时先取景。
- 前推仍只检查腕图按钮中心横向位于两指之间，新模式独立定位双指后计算；不增加高度、深度或闭爪条件。
- 历史消息、工具调用配对、64K 压缩、停止、采图失败不重放及共享执行语义保留。网页用保存快照显示定位叠层，区分实时视频和决策观测。
- 完成报告引用本次亮灯及之后撤回观测，独立核验图像证据。定位与计算结果不充当接触或任务成功证明。

## 对问题的解释边界

本次接线让“选了哪个对象、位置是什么、为什么没有可用关系”成为可检查记录。A8没有再次生成原运行的错误下降建议，但直接原因是定位不可用限制了工具，而不是已经获得正确、可用于行动的关系。因此不能将“没有错误下降”写成空间理解已修复。

当前剩余瓶颈在**定位／可见性阶段**：模型能返回部分合理框点，仍可能漏掉可见指端或把完整对象标为partial。这会让新流程进入取景／重新观察，仍可能出现没有实际调整的循环。我们没有放宽完整定位条件来掩盖这个问题，也没有把partial框点当作可靠接触位置。

此前35项诊断中，简短单图定位问法能够找准部分点；本次使用生产双图、按钮框／箭头框／指端／可见性等更多字段，条件不同。两者的差异说明先前小实验的成功不能直接推广到当前多字段双图请求，尚不能唯一确定是双图干扰、指端定义、可见性判断或其他因素。
