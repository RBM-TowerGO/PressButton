# 取景阶段、视觉冲突恢复与三帧检查

本次落实 direct 模式的取景阶段和冲突恢复，并使用运行 `20261102_120741_0ca36af5` 的第 1、4、8 轮保存图片进行仅模型检查。没有启动机器人，没有发送真实运动命令；thinking 仍关闭，案例选择参数未改变。

**流程修改已完成；三帧视觉判读尚未通过。** 三帧头图缺少按钮及接触指端，模型均正确判断取景不可用。腕图定位到目标的大致区域，但按钮框偏左、指端均标为部分可见，程序输出的正式上下关系为未知。不能把未知或者没有再说“在下方”算作判断正确。

## 运行行为

direct 入口默认先进入 `get_view`。独立 `inspect_view` 请求只接收当前头部和腕部两张原图，定位按钮框、接触标记框和所指物理手指前端。模型不生成运动建议。程序根据位置计算图像平面上下／左右关系，仅用于提供可审查的视觉证据；没有像素到毫米转换，没有自动生成 XYZ。

在头图尚不能辨认面板、目标按钮及物理接触前端时，动作模型只能选择头部调整、重新观察或报告无法继续。工具列表、候选校验及发送前校验都执行这个阶段限制。模型自行选择绝对头部角度，约 +30°仅是提示中的取景参考；初始头图已充分可见时，无须额外低头。头部命令发送完成后必须对新图重新检查，不能凭发送完成放行手部运动。

动作模型与独立进展复核对当前上下／左右关系明确矛盾时，进入 `recover_view`。双方观点保存为模型分歧，不把复核认定为事实，也不自动反向移动。当前观测被锁定在恢复阶段，即使后续回答改口同意复核也不能直接执行手部动作。只有获得新的观测并通过独立取景检查，才恢复手部工具并建立新的进展比较起点。普通重新观察和零位移不会自行清除未解决的进展问题。

原有正 X 的腕图横向两指之间检查、工具参数、共享键盘执行器、命令幂等和单动作在途均保持。取景与冲突恢复是新的阶段限制，不是到位、接触或任务成功判定。模型格式修正仍无次数上限；人工停止、迟到响应丢弃和真实请求失败处理仍有效。

## 仍然存在的限制

- 可用取景仍由模型定位判断，代码不能证明定位正确。三帧小检查未证明精细定位可靠，也没有检查真实低头后的画面能否通过。
- `ready` 后正常手部运动不会每轮重新调用定位；日志中的取景确认可能来自此前观测，网页分别标明两个观测 ID。头部改变或冲突恢复会重新检查。
- 如果动作模型直接接受了错误复核、没有显式分歧，冲突恢复不会自动触发。本次修复的是冲突后的流程，不是消除了所有视觉误判。
- 完成仍需要本次亮灯和后续撤回证据，任何定位／取景通过都不等于任务成功。
- 零动作取景中断会保存完整运行日志；本次没有扩展原有 FailureCase 的“三个已完成动作拼图”注入格式。

原 direct 一键命令会启用新流程。本次没有启动真机。后续应先解决可审查定位中的偏差和不确定性，不能依据这次代码回归就认定可以稳定自主按压。
