# 腕图明确方向规则与数值选择

2026-11-02。用户希望明确规定偏差方向对应哪个轴及符号，模型主要选择具体毫米幅度。默认 localized 流程已接入；本次没有连接、启动或向机器人发送动作。

## 当前规则

参照为腕图中箭头所指的物理指端，目标为按钮可按面，不是面板整体、贴纸中心或图像中心。

| 按钮可按面相对物理指端的位置 | 对齐方向 | 预期腕图变化 |
| --- | --- | --- |
| 完全在左侧 | +Y，机器人左 | 按钮向右靠近指端 |
| 完全在右侧 | -Y，机器人右 | 按钮向左靠近指端 |
| 完全在上方 | +Z，抬高手 | 按钮向下靠近指端 |
| 完全在下方 | -Z，降低手 | 按钮向上靠近指端 |
| 某轴上指端已落入按钮面区间 | 该轴为0 | 不追求精确中心重合 |

因此按钮左上方对应 `[0,+a,+b]`；模型根据实际反馈选择 a、b，偏差大时较大幅调整，接近后减小。不设置固定像素到毫米比率或位移上限。正X仍须独立通过当前腕图二维重叠检查。

方向表适用于本装置当前未镜像腕图、相机安装及保持的手部朝向，不是通用相机变换，不能套用于头部画面。

## 接入方式

1. 系统提示和动作工具描述明确方向表；复核提示补全XYZ轴含义，避免把Z称作前伸。
2. `wrist_direction_rules.build_hint()` 从本轮规范化腕图按钮框和指端计算条件性Y/Z符号。未知为null，不当成0；局部可见保留条件说明，不当作完整按钮或前推许可。
3. 动作请求末尾追加绑定本轮观测ID的 `CURRENT_WRIST_ALIGNMENT_DIRECTION_RULE`，直接提供方向；每轮保存 `wrist_direction_rule.json`，动作台账保存该提示，历史消息不改写。
4. 要求沿已证实改善且尚未越过目标的方向继续，不能刚用正Z恢复视野又无依据改负Z；不能只凭按钮框变大导致 `error_button_units` 变小来认定改善。

这是明确的方向提示与每轮算好的符号，尚未添加Y/Z符号硬校验。模型仍输出原XYZ接口，执行器不替换、裁剪动作。定位与物理指端识别仍可能错误，因此提示要求与当前原图核对；本改动不保证视觉正确或任务成功。
