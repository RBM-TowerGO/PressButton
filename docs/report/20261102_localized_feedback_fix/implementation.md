# 坐标修复与无进展复核的实现

本次修改针对 `localized` 默认流程。没有启动、停止、接管或移动机器人，没有改写原始实验记录。模型回放与真机效果分开记录；下次通过原一键入口启动时加载新代码。

## 坐标接口

- 定位格式升级为 `pressb-localization-v3`。模型必须声明统一的 `coordinate_units`，提示使用 `normalized_1000`；也支持明确声明的 `normalized_01`。
- 内部统一保存为0～1，再按各相机图像尺寸换算像素。问题样本原先的 `[-259200,-250200] px` 在明确按0～1000解释后为 `[-259.2,-250.2] px`。
- 单位缺失、声明冲突、越界、非有限数、反向或零面积矩形均记录解析问题并保留未知位置，不猜单位、不裁剪。模型即使声明单位，也仍可能找错目标或在数值上不遵守声明；协议校验不能验证视觉准确性。
- `coordinate_conversion` 保存来源单位和换算依据。原始输出留在归档，进入动作上下文与压缩台账的 `model_view()` 不再重复携带未换算原文。
- 旧档只允许通过明确 `source_units` 的离线解释重算；不会凭数值大小静默转换旧日志。网页只绘制合法归一化位置。

## 复核流程

```text
新观测 → 独立定位 → 规范化偏差
                      ↓
             统计实际已发送的动作
                      ↓
       无异常：动作决策；出现重复异常：只读复核
                                         ↓
                      绑定当前观测的新决策与可检验预期
                                         ↓
                               原共享执行器
                                         ↓
                    新观测；若仍重复异常，检查上次预期
```

`localized_reassessment.monitor()` 只统计成功发送的实际命令。命令ID去重；重新观察和零位移不增加计数，也不清空已有运动段；头部、夹爪变化和失败/中断动作结束当前可比运动段。保存观测回放统计原记录动作，绝不将模型新建议当成已执行动作。

同轴同向实际运动达到3次，且没有一致的二维投影改善时触发复核。部分按钮框、不可定位的接触点或参照身份变化不能提供完整目标的改善证据。完整目标与指端可辨时，数值比较使用按钮宽高归一的偏差模长；减少至少原误差的10%且至少0.1个按钮单位才计为明确改善。这些阈值仅用于调度复核，不是接触判断或执行器限位，也不是已标定视觉伺服。

连续正X达到3次总会复核接触假设，因为二维误差变小不能证明可以接触或已经触发。默认thinking仍关闭。独立请求使用运动段开始和当前的双视角4张图、实际命令和规范化偏差；不带历史动作理由或示范。输出包括观察到的效果、“仅仅距离不足”假设是否有依据、替代解释、灯态变化和下一项检查，均标记为模型判断。

复核后新的动作响应必须附带 `reassessment`：当前观测ID、复核ID、接受还是以具体画面反证提出异议、证据、预期画面变化、没有变化时要重新考虑什么。程序校验结构和绑定，剥离这些辅助字段后再将原有XYZ/head/gripper参数交给共享执行器，不自动反向、裁剪或替代动作。

如果继续重复运动而异常仍在，后续复核使用上次已执行预测对应的前后图，显式输出 `prediction_check=met/not_met/unknown`。初次无预测则输出 `not_supplied`。两图之间的零位移等实际命令也保留在 `commands_between_images`，不因不计入运动次数而丢失边界。

定位、复核、格式修正、压缩和动作请求均沿用停止检查；迟到响应不能触发执行。格式修正不设次数上限，遵循已有约定。无效深度、未知定位、单侧手指按压不被新增为动作禁用条件。

## 归档与兼容

- 每轮保存 `hypothesis_review/trigger.json`；触发时保存独立请求、原始响应、有效结论、metrics及错误。
- `decision.json` 保存验证通过的动作复核元数据，明确标注 `validated_proposal_not_execution`；它不是执行回执。
- 网页显示复核阶段、前后观测ID、假设结论、预期核验及各阶段token/耗时。未触发轮和旧档不会伪装成已复核。
- 失败案例读取兼容旧定位v2和新v3，以及复核中断、没有动作的轮次。
- 保留持续历史和64K压缩；内部动作统计不会因压缩清零。最近轮次保留复核与动作，较早台账保留相关判断和来源。
- 部署入口递归打包 `src/pressb`，新增模块随现有部署进入包；机器人HTTP schema、共享执行器、命令去重和单动作在途机制不变。

## 验证和剩余问题

相关Agent扩大回归634项通过、4项环境跳过；网页新增渲染分支另经工具V8执行通过。随后包含最后改动的定向复查34项通过，覆盖零位移边界、实际动作计数、重新观察、旧/新坐标、只读复核、预测字段、停止后的迟到响应、格式修正、压缩与共享执行参数。两个测试集合有重叠，不能相加当作独立用例总数。

模型实验见 [README](README.md) 和 [最终生产流程回放](production_smoke_final/report.json)。最终复核认为连续前伸没有改善，动作改为横移，但仍出现“向机器人右移动”与 `+Y`（机器人左）矛盾。无图符号题和给定局部反馈的符号题答对，不能证明模型在完整视觉上下文中会可靠地将关系、动作符号与理由一致结合。

因此，本次完成的是单位修复、显式复核流程及故障分离；**没有证明视觉控制问题已解决，也没有真机任务成功证据**。现有程序不对自然语言理由和XYZ做自动语义核对，不能因为结构合法就认定动作方向正确。
