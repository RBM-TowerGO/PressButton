## 已完成的受控回放

原始第 15 轮输入含 3 张成功案例图和 15 组实时双视角，共 33 张。此时前 14 条命令已发送完成，其中最后 13 次连续前伸，累计命令位移 95 mm。原定位把数百量级坐标当作 0～1 数值，给腕图算出了 `[-259200,-250200] px`；按明确的诊断假设 `normalized_1000` 换算，应为约 `[-259.2,-250.2] px`。

## 能分清什么

1. **接口错误是真实且必须修正的，但不是本帧循环的唯一原因。** A/B 的动作和理由完全相同；即使消除千倍数值污染，模型仍然前伸。这个结果不代表单位 bug 对其他帧没有影响。
2. **基本符号映射能力存在。** 无图情况下模型能按约定编码左右上下；此前真机首轮“理由写右、参数却 +Y”的错误不能简单归因于完全不懂 `-Y`。但这些题不测试从相机投影推断机器人应移动哪一轴的能力，后者仍未得到验证。
3. **动作选择没有自然利用反馈来检验原假设。** B 已提供偏差和历史，模型仍重复原动作；C 明确把连续动作的效果整理成待检验问题后，两次都改变为取景。该干预同时增加了事实聚合和复核指令，不能分别归因于二者，也不能据此推断神经网络内部的注意力分配。
4. **清空动作历史本身不够。** D 仍前伸。由于 D 同时减少历史文字和旧图片，不能严格分辨“历史锚定”和“多图干扰”的各自影响。
5. **改变动作不等于修好空间控制。** C 的转头可能有助于观察，但本次未执行，不能证明实际视野改善或任务成功；它也没有证明模型已经学会正确的 Y/Z 调整。

因此，修复应分为明确单位协议、显式无进展复核、真机验证三个层次。模型可以继续在证据不足时选择前推，但应说明新的视觉依据、预期变化及变化未出现时要重新考虑的假设，不能仅重复“按钮就在前方”。

## 补充：能否利用给定的局部动作效果选择符号

又做了两个不含图片的条件式推理题，结果见 [empirical_mapping/report.json](empirical_mapping/report.json)。题目明确假定局部线性、估计值准确、其他轴不耦合；**这些是假设，不是已经完成的机器人标定**。输出仅为符号测试，给定幅度 10 mm，不执行。

| 输入 | 应选符号 | 模型回答 |
|---|---|---|
| 历史首条 `+Y20` 前后，腕图估计 `dx` 从 `-256.0` 变为 `-262.4 px` | 若此局部响应稳定，减小绝对偏差应选 `-Y` | `[0,-10,0]`，解释 +Y 让偏差更负，正确 |
| 人工反转响应符号：`+Y20` 让 `dx` 从 `-256.0` 变为 `-249.6 px` | 同样假设下应选 `+Y` | `[0,+10,0]`，解释 +Y 缩小绝对偏差，正确 |

两题均一次合法调用、无修正，输入分别 2102/2103 token、输出 88/87 token，耗时 8.58/8.49 s。第一题数字来自第 1/2 轮模型定位的规范化换算，不是人工测量；第二题明确为合成控制。

这比单纯背诵“右=-Y”更进一步：在压缩成明确数值关系、且任务假设已经给定时，模型能够从动作效果选出相应符号。但结合下方生产冒烟中仍出现的“右=+Y”矛盾，当前限制仍在于视觉、多轮历史、任务选择和动作编码组合后的可靠性，不能用这两题证明真实空间控制已通过。

## 时间与统计限制

所有请求共享同一服务，没有清空服务缓存。B 第一次改写了历史前缀，耗时明显高于第二次，服务又没有返回单请求缓存统计，因此这些时间只能描述本次调用，不能作为提速/减速比例。两次温度 0 重复不是两个独立场景，不能估计通用正确率。

包括 12 个 A/B/C/D 与符号请求、2 个条件式反馈题、首次生产冒烟 3 个请求、最终 schema 复核/动作 2 个请求，合计 **19 次模型请求**。格式合法 19/19、格式修正 0 次；这不是视觉或动作正确率。总输入 525180 token、总输出 2390 token，各 HTTP 阶段记录耗时合计约 324.2 s。最终版复用的定位只计一次，详细统计见 [model_request_summary.json](model_request_summary.json)。所有临时模型隧道在脚本结束时关闭。
