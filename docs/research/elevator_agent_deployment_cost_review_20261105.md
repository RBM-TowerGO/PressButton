# 电梯按钮 Agent 的跨面板泛化与部署成本调研

调研日期：2026-11-05（Asia/Shanghai）。范围：当前支线、Qwen 工具调用 Agent，以及外部直接相关研究；不使用本项目历史 Qwen＋JEPA／VLA／RL 支线作为论文依据。外部模仿学习和 VLA 工作仅用于比较部署需求。此次仅检索、读取代码和新增本文，没有运行机器人、训练或模型请求。

**结论：值得研究“无需目标面板示范、无需目标面板模板和人工补偿的按钮操作”，但不能把其他方法描述为每换一个楼层都必须重训。** 已有 OCR 系统、目标参数化策略和基础模型都具有不同程度的跨目标泛化。Agent 的潜在优势应由新增电梯时的人工工作量、首次部署成功率、每次执行成本共同证明。

## 1. 研究范围与证据规则

本文区分四种变化：

| 变化 | 例子 | 不能混淆的成本 |
|---|---|---|
| 同面板换目标 | 从按 3 楼换成按 8 楼 | 新目标不一定需要新模型或示范 |
| 换面板／电梯 | 字体、布局、大小、标签位置、按钮形态变化 | 可能需要模板、标定、站位或控制适配；不一定需要训练 |
| 换所在楼层／建筑 | 相同外呼按钮出现在另一个走廊 | 建图与导航点成本不能误算成按钮识别训练 |
| 换机器人 | 相机、末端、关节和控制 API 变化 | 具身适配与手眼标定一般属于机器人级成本 |

任务边界也分开：P 为已处于面板可交互范围内的选键、接近、按压、验证、撤回；E 为从远处导航、呼梯、进出轿厢、到达目标楼层。本文推荐先研究 P。若人工摆放机器人、移动面板、调整手臂或取景，这些应记录为准备成本；不能据此宣称完成 E。

证据标记：**论文事实**＝作者论文明确报告；**代码事实**＝本次读取的公开实现；**推断**＝依据依赖关系推导的部署步骤；**未报告**＝当前查阅材料没有给出，不等于零。本文不虚构每部电梯需要多少工时、GPU 小时或人民币。

检索以论文全文、作者项目页、作者代码为主。部分 PDF 通过作者站／会议镜像下载后阅读；IEEE TIM 2021 的完整正文未取得，明确限制其结论。所有工作均为作者报告，未在本机复现。

## 2. 文献证据与新增电梯需要做什么

### 2.1 Klingbeil 等，ICRA 2010：陌生电梯上的检测＋OCR＋几何操作

**论文事实。** 训练检测器、字符识别与标签顺序模型，再在未见电梯运行。机器人需视觉／机械臂和传感器标定；实机由人放在面板可达范围内。3 部陌生电梯、14 次试验中按压成功 13 次。没有为测试电梯逐键收集动作示范。原文 §§III–V。[论文与会议镜像](https://fileadmin.cs.lth.se/ai/Proceedings/ICRA2010/MainConference/data/papers/2076.pdf)

**部署推断。** 在支持的标签和布局内，换楼层主要是改变目标；换面板可直接尝试识别。超出字符字典、标签相对位置或几何假设时，需另行验证或扩展识别。它反驳“所有传统方法都依赖目标电梯重训”，但未给出现代意义的部署工时或大规模跨电梯可靠性。

### 2.2 OCR-RCNN，IROS 2018／IEEE TIE 2021 在线发表、2022 卷期

**论文事实。** 将按钮检测与字符识别分开；发布 2,005 张面板图、21,767 个按钮标注。[TIE 论文](https://ieeexplore.ieee.org/document/9324975/)

**代码事实。** 作者提供冻结模型，目标包括未访问过的电梯；README 报告 GTX950M 约 6 FPS，依赖旧版 TensorFlow／Python。它是感知实现，不等于完整按压控制。[作者 README](https://github.com/zhudelong/ocr-rcnn-v2/blob/master/README.md)

**部署推断。** 新楼层数字在字符识别覆盖范围内时，不需要创建“第 N 楼”独立检测类别；换面板先测试冻结感知，再处理失败分布。要按下按钮，仍需相机与机器人坐标变换、接触端定义和通用运动控制。需要更新旧软件栈属于实现维护成本，不是该方法天然的逐面板训练要求。历史帧率不能直接和本项目端到端任务时间比较。

### 2.3 Zhu 等，IEEE TIM 2021：Eye-in-Hand 电梯操作

作者仓库列出该完整操作系统论文，但本次 IEEE 页面受验证限制，未取得完整正文，因此不填它的具体轨迹数、逐电梯调参项目或成功率，也不根据论文标题推断其必须逐电梯训练。[作者论文索引](https://github.com/zhudelong/ocr-rcnn-v2#citation)、[出版页](https://ieeexplore.ieee.org/document/9295374)

它应列入优先精读清单。正式论文中需要补核：相机标定程序、粗细控制条件、测试电梯是否训练留出、按钮姿态估计是否使用面板先验，以及现场配置步骤。

### 2.4 Müller 等，ECMR 2023：面板建档＋模板匹配＋力反馈

**论文事实。** 使用公开数据训练 16 类按钮检测；安装时在正视、无遮挡条件下记录面板配置，数据库保存按钮相对位置与语义；运行时匹配模板纠错。流程依赖面板专用交互站位。腕部 ArUco 用于修正手眼误差；按压力阈值为 6 N。原文 §§IV–V。[论文](https://www.tu-ilmenau.de/fileadmin/Bereiche/IA/neurob/Publikationen/conferences_int/2023/Mueller_St-ECMR-2023.pdf)

**部署推断。** 新增同面板目标可查既有数据库；新增面板需要记录配置、登记位置和交互站位、试验可达性。未知按钮可以借助模板语义，不代表必须扩充检测器类别。关键边际成本是现场建档与验收，不是每层采集一套动作数据。论文未报告上述工作各需多少分钟。

### 2.5 Schulze 等，Frontiers 2025：真实楼宇运输系统

**论文事实。** 延续预建地图、已知面板模式和 16 类检测；用末端标记修正机器人／相机偏差。系统强调本机运行以应对楼内 Wi-Fi 中断。其目标是预定义环境中的可靠运输，并非全面消除现场配置。原文 §§3.1.2–3.1.5。[全文](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2025.1546894/full)

**部署推断。** 扩展到新建筑需区分地图／电梯入口配置和近距离按钮控制。若本项目只做任务 P，不能把对方的跨楼层建图成本全部计入按钮按压比较；可以在任务 E 的独立账本中记录。

### 2.6 Chang 等，2019：目标参数化模仿学习

**论文事实。** 使用目标行列或像素位置作为策略输入，训练部分目标后泛化到未训练目标。实机包括 4×4 按钮板；论文报告在有信息量的约三分之一目标上训练，可泛化到场景中超过 90% 的目标。原文 §IV-B。[论文](https://arxiv.org/html/1910.10628v1#S4.SS2)

**部署推断。** “换按钮就要学一条全新策略”不是模仿学习的必然要求。该方法仍需已有轨迹和目标参数；任意陌生电梯上的语义识别、标签关联和材质变化，没有由网格内插值实验自动证明。适合作为“通用目标控制器＋前端识别”的基线思想。

### 2.7 Mobile ALOHA，CoRL 2024：全身示范学习呼梯与进入

**论文事实。** Call Elevator 使用 50 条示范；每条约 45 秒，覆盖接近、按外呼键和进入，并与静态 ALOHA 数据共同训练。它不是任意轿厢楼层按钮选择实验。[论文 Fig. 3、Table 1](https://mobile-aloha.github.io/resources/mobile-aloha.pdf)

**成本推算。** 50×45 秒＝37.5 分钟，仅是演示轨迹长度合计，不包括复位、等电梯、失败采集、训练与验证，也不是作者报告的总采集工时。未报告换一部电梯必须再收 50 条，不能如此外推。增加楼层语义选择需要改变数据／条件设计并重新评估，原结果不提供直接答案。

### 2.8 CORAL，2026：按按钮任务的 LoRA 专家

**论文事实。** 电梯任务有五个变体，正文列 Floor 1/2/3、Bell、Phone；每个新变体 20 条示范，10 epochs，使用任务专家。电梯部分合计 100 条示范为直接算术推导。附录对第五个按钮名称有不一致，应以具体定义核对。§IV-C。[论文](https://arxiv.org/html/2603.09298v1#S4.SS3)

**部署推断。** 这是“逐目标采集／训练”可引用的具体实例，但不能推广到所有 VLA。按该新任务协议增加目标需要专家数据与训练；换面板能否零新增数据成功，需单独评估。其八项跨场景泛化任务并非这五个电梯按钮，不能混用结论。LIBERO 的 rank-16 存储／训练步数也不能冒充实机按钮的 rank-64 成本。

### 2.9 BUMBLE，ICRA 2025：VLM＋通用分割＋电梯技能

**论文事实。** VLM 选择按钮，GSAM 给出分割，RGB-D 与技能完成按压；流程使用力阈值、楼层地图和预定进入位置。长期记忆由离线例子筛选得到；不是目标面板无任何先验的完整乘梯实验。见 Appendix VII-A。[论文](https://arxiv.org/abs/2410.06237)

**代码事实，比摘要更重要。** README 要求配置楼层占据地图与地标。[安装说明](https://github.com/UT-Austin-RobIn/BUMBLE/blob/master/README.md)

`use_elevator.py` 按 `bld`、`floor_num` 保存特定位姿；选层调用设置 `adjust_y=True`，在 `ahg`／`mbb` 分支将目标 Y 分别修正 −0.045／−0.02 m。另有固定末端补偿与人工确认入口。[位移修正](https://github.com/UT-Austin-RobIn/BUMBLE/blob/master/bumble/tiago/skills/use_elevator.py#L466)、[位姿配置](https://github.com/UT-Austin-RobIn/BUMBLE/blob/master/bumble/tiago/skills/use_elevator.py#L580)、[选层调用](https://github.com/UT-Austin-RobIn/BUMBLE/blob/master/bumble/tiago/skills/use_elevator.py#L727)

读取版本：2026-11-05 的 `master`；文件 Git blob SHA 为 `73d5591a50adae7c1f8812c7fe9b027f9e62a0c5`。这些是公开实现中的依赖，不证明全部论文试验都使用人工确认，也不证明偏移在所有新部署都必需。

**部署推断。** 新楼层通常由 VLM 选键，无需单独训练分类器；新楼宇需要地图／地标接入，复用公开实现还需替换楼宇分支并重新验证补偿。只比较任务 P 时，最相关的是目标补偿和控制规则；任务 E 才计导航位姿。它是本项目最重要的直接对照之一。

### 2.10 Arlt 等，2025：人形机器人自主操作与求助

**论文事实。** 使用包含大致按钮位置的电梯模型，OCR-RCNN、深度平面、可达性地图与行为树；遇到人群阻挡会求助。真机按压约半数成功，作者指出标定影响明显。相关段落：Perception、Summary and Discussion。[作者全文](https://h2t.iar.kit.edu/pdf/Arlt2025.pdf)

**部署推断。** 不需要每个目标独立训练动作，但仍有场景模型和机器人可达性准备。求助节省自主控制难度，却消耗外部人工；评估成本时要将“机器人自己成功”和“别人代按成功”分开。

### 2.11 GPT-6-Astra 电梯论文，2026：通用 Agent 与经验复用

**论文事实。** 固定权重，改变身体信息和经验包；真机先校准机器人、人工放置底盘和准备姿态，成功采用人工确认接触。仿真经验由三个源运行中选出，构建成本不能只算最终成功片段。原文 §§3.1–3.3。[论文](https://arxiv.org/pdf/2609.31770)

**部署推断。** 它支持无目标坐标的在线解释与经验迁移，但未证明大量未见面板、任意楼层、零人工确认的可靠按压。Agent 的材料整理、源试验和服务等待均应计成本。本文不将其任务耗时当成现场部署工时。

### 2.12 DreamZero，2026：非 Agent 的零样本竞争路线

**论文事实。** 除结构化评估外，包含自由指令下按电梯按钮的展示；正文限制章节报告 7 Hz 运行使用 2 个 GB200。新机器人适配与目标任务零样本是不同概念。[论文 §§5、6](https://arxiv.org/html/2602.15922v1)、[作者展示](https://dreamzero0.github.io/)

**判断。** 它说明“不采集目标任务示范”并非 Agent 独有优势；电梯演示不能当作多电梯、多楼层成功率。比较应同时检查可用具身模型、硬件、推理开销和目标面板上的实际成功率，不能仅凭大型预训练成本判定其用户部署必然昂贵。

### 2.13 外挂式 IoT 按键装置，Applied Sciences 2023

**论文事实。** 在原面板上加装带舵机的装置，通过无线指令间接按原按钮，无需机器人识别并接触按钮。[论文](https://www.mdpi.com/2076-3417/13/6/3971)

**部署推断。** 成本主要是机械适配、安装、按键映射和维护，随新增面板而发生。它不是本项目同设定算法基线，但在真实商业部署比较中不能忽略：少量固定电梯、高频任务可能适合一次安装换低运行成本。本文不引用未核实的设备报价。

### 2.14 公共数据与邻近研究

可使用 2021 年电梯按钮分割／字符识别数据集（3,718 张图、35,100 个按钮标注）做离线识别覆盖测试；它不提供跨面板物理按压证据。[论文](https://arxiv.org/abs/2103.09030)

2026 年 *You’re Pushing My Buttons* 使用按钮状态辅助监督和指尖音频研究轻柔按压，主要关注接触质量，不是目标电梯免配置部署。若未来加入音频，可作为相关工作，但不应因此转移本文主问题。[论文](https://arxiv.org/abs/2604.05954)

## 3. 横向比较：新增楼层和新增电梯分别需要什么

下表是基于以上依赖的归纳，不是跨论文同协议排名。“可能”意味着条件性推断；NR 表示未报告。

| 方法族 | 同面板换目标 | 换电梯／面板 | 必须搭仿真吗 | 主要成本位置 |
|---|---|---|---|---|
| 通用按钮检测＋OCR＋几何控制 | 改目标标签，通常不训练 | 冻结模型可直接试；识别覆盖不足时再适配 | 否 | 一次性识别训练、机器人标定、控制集成 |
| 已知面板模板＋检测 | 查询模板中目标 | 采面板配置，注册位置和语义，配置交互站位 | 否 | 每面板建档、调试、地图维护 |
| 目标参数化策略 | 改行列／像素目标，可插值 | 目标获取与外观泛化需验证 | 否；研究可用仿真 | 一次训练和目标参数提供 |
| Mobile ALOHA 式任务策略 | 原呼梯实验未验证任意选层 | 跨电梯追加数据量 NR | 否 | 遥操作、复位、训练、验收 |
| CORAL 新任务专家协议 | 每个新变体提供示范和专家训练 | 面板变化的追加成本 NR | 实机部分不必 | 数据采集、专家管理、训练 |
| BUMBLE 式 VLM＋技能 | 模型选择目标，通常不重训 | 地图／站位／公开实现补偿需接入与验证 | 否 | 技能工程、现场配置、VLM 推理 |
| 通用机器人 Agent | 在线理解新目标 | 理想目标是只给当前观测；目前需实验证明 | 否；仿真可用于开发 | 身体接口、在线计算、试探、重试 |
| 零样本机器人基础模型 | 指令条件化 | 能力与具身覆盖内可尝试，按钮专项证据不足 | 否 | 具身兼容、模型运行资源 |
| 固定外挂按键装置 | 按已有映射发命令 | 机械安装与映射 | 否 | 每面板硬件、安装、维护 |

因此，论文不能声称“避免了其他方法必需的电梯仿真搭建”。检索到的多种主要方法直接使用真实图像、真实机器人或模型控制。评测所需的实验台也应与策略学习必需的场景建模分开。

## 4. 部署成本应怎样定义

### 4.1 三层成本账本

1. **机器人／系统级一次成本**：驱动与工具接口、相机与 TCP 标定、控制器集成、通用提示词与技能开发、模型部署、相关训练和硬件。研究团队自行训练基础模型的成本与普通用户下载模型的成本分别报告，对 Agent 和非 Agent 对称处理。
2. **新电梯的边际接入成本**：访问现场、图片与示范、按钮标注、面板模板、地图／站位、局部参数修改、微调、测试、返工与复位。明确哪些只在第一次出现的面板类型上做，哪些每一部都做。
3. **每次任务成本**：完整运行时间、推理、机械执行、观察与等待、失败重试、人工救援、能耗和网络。并行部分不重复相加；同时记录关键路径耗时与资源占用时间。

训练数据为零，只能说明其中一项为零。人工把正确位置写入提示词、在新面板试十次后改阈值、筛选成功经验或手动框按钮，也属于目标特定适配。

### 4.2 先报告原始量，再统一货币

| 类别 | 必须记录的原始量 | 防止误记 |
|---|---|---|
| 人工 | 主动操作分钟、必须在场等待分钟、人员数、技能等级 | 监督人员不改策略也应记录；不能只记按键时间 |
| 数据 | 轨迹条数／时长、图片数、标注对象数、失败数据、复位次数 | 不能把训练帧数等同独立示范数 |
| 配置 | 修改文件、参数、提示词、模板、面板坐标、提交差异 | 自动生成配置和人工生成配置分开 |
| 学习 | GPU 型号、GPU-hours、训练墙钟、调参轮数、权重数量 | 不同 GPU 小时不能不加说明直接相加比较 |
| 在线推理 | 每模块调用次数、时延 p50/p95、输入／输出 token、图像数、缓存命中 | 本地 token 是负载量，不自动等于 API 账单 |
| 机器人 | 占用分钟、运动／观察次数、复位／重试、硬件与能耗 | 包括失败与中止，不只统计成功录像 |
| 结果 | 正确目标、触发、撤回、误按、介入、未完成 | 接触不能替代真正按钮触发 |

本地模型没有逐 token API 费，但有显卡／设备折旧、电费、运维和空闲容量；远端 API 还要计请求、图片或 token 账单、网络与数据策略。先实测硬件与实际使用，再报价；本文不提供臆测单价。

### 4.3 总成本和盈亏点

统一为可比货币后，可采用如下评测模型；这是本文提出的核算方式，不是文献报告结果：

\[
C_{\rm total}=C_{\rm shared}+\sum_{e=1}^{E} C_{\rm setup}(e)
+\sum_{j=1}^{N} C_{\rm run}(j)+C_{\rm maintenance}.
\]

各项应包含失败与恢复成本且避免重复计费。单位成功任务成本取总成本除以完成指定目标的独立成功任务数。一个任务重试三次后成功只算一个完成任务。零成功则报告不可估计／无穷，而不是省略该配置。

若 A 为 Agent，B 为专用方案，假设运行成本按任务稳定，且 A 每次更贵，则近似盈亏点为：

\[
N^*=\frac{C_{\rm shared,B}-C_{\rm shared,A}
+\sum_e[C_{\rm setup,B}(e)-C_{\rm setup,A}(e)]}
{\bar C_{\rm run,A}-\bar C_{\rm run,B}}.
\]

只有分子分母为正、任务质量与可靠性可比时，这个简式才有解释力。现场频率不均、成功率不同或维护频率变化时直接比较实测累计成本曲线，不强行套一个阈值。

**可检验的经济假设：** 很多异构电梯、每处少量任务，免现场适配更有价值；少数固定电梯、高频重复运行，专用控制或固定装置可能更经济。不能先验断言 Agent 全面更便宜。

## 6. 推荐的比较实验

### 6.1 最小基线集合

| 基线 | 为什么需要 | 公平条件 |
|---|---|---|
| 通用按钮检测／分割＋OCR＋几何控制 | 排除“只要能读数字就够了”的解释 | 提供合理通用 OCR，不故意限制楼层类别 |
| 已知面板模板＋同一控制器 | 测量现场配置换可靠性的收益 | 实际计时建档，记录照片／按钮语义和位姿 |
| 同一 Qwen 定位＋固定局部技能 | 分离基础模型感知与 Agent 决策收益 | 同模型、同传感器、同执行器 |
| 当前 Agent 零目标面板适配 | 主方法 | 提示词和参数在留出测试前冻结 |
| Agent 有限自主探索／记忆 | 测试在线适应的代价与收益 | 限制时间、调用与动作预算，单独报告首访和复访 |

如果资源允许，再加入一个目标条件化学习策略；外部 CORAL/Mobile ALOHA 的协议是文献比较，未移植复现时不能声称实测胜过它们。

严格区分两张结果表：**同机器人同传感器的实测对照**与**异构论文的报告依赖表**。本报告属于后者。

### 6.2 切分方式

以整块面板或整部电梯留出；同品牌同布局不同楼层可作为一个分层，但不能让大量近重复面板充当独立泛化样本。区分新目标／旧面板、新面板／已见标签、新面板／新标签语义以及接触几何变化。

开发阶段可使用实验台；测试阶段至少包含未参与规则开发的真实面板，并将实验台和在役电梯结果分开。不同字样贴在同一机械按钮上只能验证部分语义泛化，不能证明接触泛化。按钮高度还受机器人可达性限制，应预先声明任务范围，不能只在失败后剔除不可达样本。

### 6.3 两种部署预算

- **零目标适配**：没有目标面板图片、示范、模板、补偿或提示词改动；允许所有方法读取当前传感器。共享机器人标定和开发数据披露。
- **有限适配预算**：建议比较 0／15／30／60 分钟的现场预算，记录每种方法实际采用的策略；这是拟议实验网格，不是文献测量值。训练可在计时内并行，但人时、GPU 时和墙钟分别记录。

不以失败运行作为不计成本的“预热”。Agent 自主试探、人员复位和非正式 prompt 修改都进入预算。为避免记忆泄漏，首次访问实验重置上下文与目标面板缓存；重复访问允许保留的内容预先声明。

### 6.4 样本与统计

可先做 3 块开发面板，再用约 6 块留出面板、每块 4 个普通目标、每目标 3 个配对初态做先导实验；每方法 72 次，实际数量取决于设备和按钮覆盖。这不是统计功效保证。正式规模根据先导效应、面板间差异和人工预算决定。

以面板为聚类单位给出置信区间，同时报告每面板结果；不能将同一面板数百帧或连续重复当作数百个独立电梯。方法顺序随机化并共享初态，错误目标、超时、基础设施异常和人工中止分别分类。重复任务用相同验收标准，不把研究人员确认接触与传感器确认触发混为一类。

### 6.5 主结果图

1. 首次部署成功率 vs. 现场人工分钟。
2. 正确触发率 vs. 总任务时间／模型调用预算。

## 7. 低运行成本的 Agent 设计建议

以下是待验证方案，不是已实现能力：

**优先消除重复推理。** 一次观察形成带置信度的按钮—标签—可按区域表示；局部追踪和短程对齐尽量使用已有反馈，只有目标丢失、预测效果冲突或触发不确定时才重新请求 Qwen。每个局部技能必须返回可核查状态，而不是无条件成功。

**将跨面板适应放在参数获取层。** 保留通用机器人运动与按压工具，但由当前图像／深度生成目标、方向和停止条件，避免出现 `building_id -> correction` 的人工分支。若需要在线估计局部映射，记录交互次数，并与简单视觉伺服比较。

**缓存与有效性一起保存。** 初访自动建立的信息可降低复访成本，但要能检测面板位置、布局和观测条件变化。展示零训练时还应披露在线存储和记忆检索成本。

**本地与远端分别衡量。** 本地模型重点看设备占用、时延与能耗；远端模型看账单与网络稳定性。不能把当前执行器发送频率当成 Agent 决策频率，也不能把单个动作模型请求时延当成整轮总时延。

## 8. 推荐论文定位与下一步

推荐问题：**在不采集目标电梯示范、不人工登记按钮位置与布局、不调目标电梯专用补偿的前提下，Agent 能否以可接受的在线成本完成不同面板上的指定按钮操作？**

潜在贡献依次是：

1. 清楚定义并测量面板级部署成本，而非只报告成功视频。
2. 在线生成任务相关几何与动作参数，以反馈修正替代面板专用偏移。
3. 用低频语义决策与局部执行减少调用，证明部署成本和运行成本之间的权衡。
4. 发布按面板留出的协议、全部失败、配置差异和人时记录。

暂定题目：*Elevator Button Agents without Panel-Specific Adaptation: Generalization and Deployment Cost*。在跨面板实验完成前使用研究目标语气，不宣称已经实现。

近期行动：先整理当前依赖，冻结一个无示范版本和同 Qwen 固定技能基线；选两三块未见面板做配对先导，记录每一次人为修改和完整运行成本。用结果决定主要投入在线几何适应还是调用效率，而不是先扩张到完整乘电梯。
