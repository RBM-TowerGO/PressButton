# 开发任务与验收清单 v1.0

P0/P1 的已完成项关联 [2026-10-26 实测报告](results_p0_p1_20261026.md) 及本次实现/报告提交；P2～P5 尚未完成。不要用计划参数填充实测字段。

## P0：固定部署契约

- [x] 核验两份模型 SHA-256、processor、10 维顺序、归一化及任务文本。
- [x] 明确模型输出为绝对目标；夹爪动作 0/1、反馈连续，头部目标不被常量覆盖。
- [x] 建立配置模板、启动校验和运行日志 schema；执行必需字段缺失时拒绝 execute。
- [x] 记录 SDK 归档版本、代码、环境及数据契约版本；P0/P1 不导入 SDK，不创建控制客户端。实时采集和当前机器人 SDK 版本复核留待 P2。

交付：配置模板、协议定义、核验报告。测试至少覆盖错误权重、旧 joint8 配置、错误 processor／契约身份、空控制参数。

## P1：5090 离线推理

- [x] 实现 joint10 policy loader 与 server，支持显式选择 2000／8000 权重。
- [x] 用原验证集 48 个固定 anchor，分别测试两份模型；输入处理和归一化对齐训练实现。
- [x] 检查输出 `(7,10)`、全部有限；反归一化与夹爪阈值正确；记录逐维、逐 horizon 误差。
- [x] 对同一权重、同一 seed，比较直接调用 policy 与 HTTP 调用结果；误差范围在报告中明确，不因 BF16 非确定性随意放宽。
- [x] 测量模型加载、首请求、至少 20 次 warmup 后 200 次推理的耗时分布与峰值显存；保存每次样本编号。

进入 P2 条件：两份权重均可运行，接口与数值校验通过；如只能在降精度／修改推理步数下运行，先记录新配置并与原输出比较。32 GB 显存是否足够以实测为准。

## P2：有线通信与只读真机采集

- [ ] 检查 `S1B` 有线连通性及实际网口路由；记录机器人与工作站 IP，不修改无关网口。
- [ ] 确认头部／右腕相机来源、颜色、尺寸、帧率，以及右臂／右夹爪／头部状态映射。
- [ ] 保存原 header 和机器人接收时间，验证时间映射的单调性，测量跨流偏差、帧年龄和丢帧。
- [ ] 建立本地绑定的推理服务和 SSH 隧道；健康检查核对模型／契约 hash。
- [ ] 连续至少 10 分钟只读采集与请求，统计带宽、请求 RTT、超时、重连和缓冲占用。

进入 P3 条件：没有状态维度／单位／图像顺序错误；所有不合格观测被明确拒绝；没有初始化控制客户端或下发动作。网络连通成功本身不算部署通过。

## P3：影子模式与假执行器

- [ ] 实现默认 shadow，记录实时预测但不构造 SDK 控制客户端。
- [ ] 用可控假时钟、假服务器、假执行器测试 30 Hz 消费和 7 点 deadline；覆盖刚好在 deadline、全部过期、仅剩末点及替换旧队列。
- [ ] 测试重复／乱序／错误 session 响应、模型 hash 变化、超大请求、非法 dtype／shape、NaN／Inf、服务崩溃、隧道中断及恢复。
- [ ] 验证慢网络不会阻塞控制线程；断线不会继续执行旧动作，也不会重连后自动恢复 EXECUTING。
- [ ] 实时影子运行至少 10 分钟；测试两份 checkpoint，并记录原始目标变化、夹爪切换及头部目标偏差。
- [ ] 分解采集年龄、网络 RTT、服务端处理、等待调度、实际可执行窗口；保存 p50/p95/p99 与最坏值。

首版进入 P4 的工程门槛：在选定测试场景中，有效响应比例和可消费队列覆盖率均 ≥99%，机器人观测参考时刻至响应接收的 p99 <200 ms；无未识别的时间域、无默默执行过期目标。此门槛为预留 233 ms 窗口余量的候选工程要求，仍须同时核验约束和停止能力，不是机器人安全性的充分证明。若不满足，停留在影子模式优化，不能只放宽 TTL。

交付：影子日志、延迟分解报告、异常注入测试结果。若网络格式或动作调度需要变更，先升级协议／配置并复测。

## P4：SDK 与受控运动

- [ ] 依据 SDK、机器人配置和现场验证，填写每个执行关节的位置／速率／偏差限值、头部允许区域及停止处理顺序。
- [ ] 核验 `control_way/use_wbc/add_default_torso` 对实际关节及非控制部件的影响；确认控制权申请、丢失和释放行为。
- [ ] 执行启动时检查模型／配置身份、近期有效观测、状态范围、人工启用和硬件急停。
- [ ] 先用预定义小幅目标测试映射、方向和单位，再在示范附近起始姿态接入模型。不要用未核验模型输出做首次映射检查。
- [ ] 核验只向允许部件发送目标；夹爪端点正确；头部实际保持误差在已填写的容许范围内。
- [ ] 做人工停止、网络断开、队列耗尽和服务故障试验，记录实际停止延迟及最终状态。

进入 P5 条件：全部待定执行参数有证据，人工停止和故障路径现场验证通过，现场操作者确认可继续。安全限值和停止延迟要求必须在试验前确定，不能在看到结果后修改门槛。

## P5：按键任务对比

- [ ] 固定任务 instruction、相机位置、起始姿态、按钮位置与成功判据。
- [ ] 首轮每个 checkpoint 10 次，采用相同 10 个起始条件配对；交替安排两模型顺序，记录所有尝试。
- [ ] 成功需由实际按钮／面板反馈确认，具体灯光或状态信号在开测前写入配置；定义每次最长任务时间。
- [ ] 分开记录成功、未触发、动作超限、头部偏离、网络故障和人工中止；不能把中止试次从总数中静默删除。
- [ ] 报告按键成功率、耗时、头部实测保持误差、夹爪切换、最大目标变化、过期比例及停止事件。

首轮 10 次／模型仅用于工程验证和发现问题，不据此声称稳定泛化。后续扩大试次、场景及姿态覆盖时另行规划；上线／常态使用条件需根据真实结果确定。

## 最小自动化测试矩阵

| 子系统 | 必测场景 |
|---|---|
| 归一化 | state10/action10 往返、头部常量、夹爪 action 身份映射、连续反馈超端点、NaN 拒绝 |
| 图像 | head/right 顺序、RGB/BGR、640×360 右腕、错误大小、resize 与训练一致 |
| checkpoint | 两份权重、哈希错误、joint8 拒绝、缺失 key、processor 缺失 |
| 协议 | shape/dtype/大小限制、无 pickle、session/id 匹配、错误响应无动作 |
| 调度 | fake monotonic、过期丢弃、乱序、队列替换、tick 抖动、无未来点、无跨 session 动作 |
| 执行器 | shadow 零 SDK 控制调用、限位／速率拒绝、控制权丢失、超时、人工停止、禁止自动重启 |
| 记录 | 原始预测与实际目标均保存、图像丢帧可见、磁盘故障可见、配置／模型可追溯 |

## 实测报告模板

每个阶段报告至少包含：

- 日期、操作者、代码提交、模型 step/SHA、SDK 与部署配置 hash。
- 机器／GPU／环境、IP 与传输路径、测试模式、持续时间／请求数／试次数。
- 已通过项目、失败项目、原始日志路径、复现命令和修复后的复测结果。
- 推理与端到端延迟、内存、丢帧／过期／停止统计；真机阶段另含实际任务结果。
- 尚未证实的假设、下一阶段是否允许进入及理由。

建议在实现后将摘要放入本目录的带日期结果文件，大视频和逐请求日志放 `outputs/s1b_deployment/`。README 更新状态时引用具体证据，不删除失败记录。
