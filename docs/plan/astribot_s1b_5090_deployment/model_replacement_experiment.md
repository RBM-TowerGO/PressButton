# S1B 按钮接触失败：换模型实验设计

日期：2026-10-27。状态：代码与已有记录检查完成，尚未实现新骨干训练入口、下载新权重、提交训练或运行机器人。

用户反馈：当前策略能接近按钮，但按不准或按不下。目标是验证模型替换能否提高真实触发成功率。

## 当前证据与边界

- `configs/vlajepa_s1b_real_joint10_mixed_hpc2.yaml`：Qwen3-VL-2B-Instruct、VLA-JEPA、双视角、state/action 10 维、未来 7 步。
- `training/s1b_real/runtime/starVLA/model/modules/vlm/QWen3.py`：动作模型使用本地骨干隐藏特征，不使用聊天 API 生成的文字。
- `src/pressb/s1b_deployment/policy.py` 的 `predict` 将头部和腕部图像缩为 224×224；训练配置的 resolution_size 同为 224。小目标细节损失是待验证假设，尚未测量接触阶段按钮在输入中的像素大小。
- `training/s1b_real/mixed_v2.md`：172 条训练轨迹、40 条验证轨迹；按首步十维归一化 MAE 选择最佳 checkpoint。此指标不等于接触或按钮触发成功率。
- `outputs/s1b_deployment/analysis_1793018984831976197/analysis.md` 记录了旧版模型的头部状态分布偏移与后期过拟合迹象。这些结论属于该次旧运行，不能直接认定为 mixed_v2 当前失败原因。
- 尚未核实最新失败的精确接触位置、末端深度误差、按钮触发反馈与图像至执行延迟；无法从“接近但未按下”唯一判定根因。

## 推荐的第一轮对照

| 组别 | 骨干 / 图像 | 用途 |
|---|---|---|
| A | 当前已训练 2B / 224 | 保留现有系统基线 |
| B | 4B-Instruct / 224 | 测试替换骨干及重新适配后的任务表现 |
| C | 2B / 448（候选） | 独立验证更清晰图像是否改善最后定位 |

先做 A/B；资源允许时加入 C。B 和 C 分开改变因素；C 必须同步训练和所有实际推理路径的预处理，并评估视觉 token 数和延迟。不能只在部署端放大输入就宣称完成分辨率对照。

B 与 A 的初始化历史不同，因此 A/B 首先是实际替换方案的比较，不能将所有差异都归因于参数量。如需研究模型尺寸的因果作用，应增加采用相同初始化策略与训练数据预算的 2B 对照。

## 4B 实验所需实现

1. 新建独立 run 和配置；从官方 Qwen3-VL-4B-Instruct 预训练权重初始化骨干。当前 init_from_config 路径依赖后续完整 checkpoint 覆盖，不能改名后原样使用。
2. 保留新骨干的 processor/tokenizer，重新加入动作 token；不能用旧 2B processor 无条件覆盖。
3. 新增显式迁移策略：不加载旧 Qwen 张量；逐项验证其他组件的键、尺寸、数据语义后决定复用或重置。动作头和 JEPA predictor 的特征接口需要适配与训练，不能仅靠 strict=False 跳过。
4. 记录源权重身份、载入/重置张量清单及新骨干配置；确保训练契约能区分新旧骨干。目前 training_contract 会移除 base_vlm 路径。
5. 使用相同 mixed_v2 轨迹划分和归一化数据契约，重新训练动作特征对齐。保留仿真预训练带来的动作能力能否迁移是实验风险，4B 通用预训练不等于已经学会机器人控制。
6. 先通过 GPU 前向/反向、权重更新、保存恢复、7×10 输出及部署预处理一致性检查。当前训练器将可训练参数提升到 FP32 并使用 AdamW/DDP；需要测量训练峰值显存，不能按 BF16 推理权重大小估算可训练性。
7. 实测端到端延迟与动作过期比例，再决定是否进行完整训练和真机对照。不要修改现有部署资产锁来绕过版本校验，应为新实验生成独立资产记录。

## 评估方式

在相同初始条件下交替运行各组，分别记录：是否接近、是否准确接触、是否实际触发、是否正常撤回。成功以可靠的按钮反馈为准；没有自动反馈时保存视频并人工标注，不以手到达面板代替成功。

首轮可用至少 20 组匹配初始条件作探索，报告成功数/试次及失败类型；小样本仅用于筛选，不能据此宣布普遍优越。对训练外的按钮位置、相机/头部姿态分别报告结果。模型选择同时参考触发成功率、接触阶段偏差、完成时间、端到端延迟和动作抖动，不仅看平均关节 MAE。

若 B 改善触发成功率且延迟可接受，继续验证 4B；若 C 改善更明显，优先保留图像细节；若各组都能对准却无法压下，则继续检查示范按压行程、末端目标与实测跟随、接触反馈及局部闭环。后者不能靠增加语言模型参数量保证解决。

## Omni 的位置

官方 Qwen3.8-Omni-Flash 文档提供多模态理解和工具调用 API。现有动作头需要 token 隐藏特征和训练梯度；公开聊天 API 不能直接满足这个接口。本次检查没有确认可供本地训练的官方 3.8-Omni 权重，所以不把它列为当前可实施的骨干替换候选。未来若取得权重和兼容训练接口，可单独评估。
