## 实现与必要修正

- 新增纯 Python 调度器、独立 30 Hz 消费线程和内存假执行器；不依赖 ROS/GPU 即可测试。生产影子入口不连接任何执行器。
- deadline 固定为原观测 monotonic＋训练 30 Hz 网格偏移，收到响应时剔除过期点，整包过期则清旧队列并拒绝。新预测替换旧预测剩余部分，不重放首点/末点，不混合、不插值、不静默裁剪。
- tick 仅消费当前一个周期内最早的未来目标。响应恰在 deadline 时该点不入队；已排队点恰在 tick 时可消费一次。所有模拟发送都验证了原始目标一致性、正确 deadline 及非过期。
- 网络异常清队列并进入 FAULT；恢复只允许新 session 的 SHADOW。假 EXECUTING 路径在队列耗尽时独立进入锁存 FAULT，不等待 HTTP 超时，不自动重新启用。
- SHADOW 的无可用点 tick 记录为 uncovered / would-fault，继续收集证据；这允许测量队列覆盖率。真正故障停止语义另以假 EXECUTING 测试验证，不以影子持续运行冒充执行器自动恢复。

初次 15 秒短测暴露真实缺口：有效统计窗口内队列覆盖率仅 **82.775%**，RTT 约 103 ms。定位并关闭 HTTP 服务端 Nagle 缓冲（`network.tcp_nodelay: true`）后，20 秒短测覆盖率提升到 **99.599%**，RTT 约 63 ms。失败和短测数据均保留。NPZ 格式、协议 `s1b-joint10-v1`、模型权重/精度/4 步推理、7 点 deadline 和 30 Hz 消费均未改；未放宽 TTL。

## 真实故障注入

故障试验与两轮性能长测分开保存。使用本次创建的明确进程编号，依次暂停/恢复服务、终止/重建隧道、终止服务并启动 step 8000。marker 由机器人本地 monotonic 记录，逐 tick 日志复核通过：

| 注入 | 实测 marker 窗口 | 窗口内 tick | 故障表现 |
|---|---:|---:|---|
| 服务 SIGSTOP / SIGCONT | 2.718 s | 82 | 约 170 ms 后无可用目标；约 1.037 s 后网络超时进入 FAULT |
| 隧道终止 / 重建 | 3.724 s | 112 | 约 37.5 ms 后进入 FAULT；恢复用新 session 的 SHADOW |
| 服务终止＋切换权重 | 52.490 s | 1,575 | 约 23.5 ms 后进入 FAULT；旧桥接器在识别新模型后明确退出 |

服务暂停时，独立消费线程持续运行；队列耗尽先于 1 秒 HTTP 超时，假 EXECUTING 测试验证此处会锁存 FAULT 并 stop。表中时间是软件检测/模拟停止条件，实际 SDK 和机械停止延迟留待 P4。

该试验共运行 92.649 秒，443 个正常响应，503 次错误/重连尝试（含 1 次超时），4 次成功恢复均使用互异的新 session，全部回到 SHADOW。FAULT 区段无目标消费、恢复未消费旧 session 目标、最终队列为空；全程没有 EXECUTING。旧模型桥接器最终以 `health_changed_requires_new_session` 退出，属于本次期望的拒绝，不作为正常长测失败混入分布。故障期间无漏 tick，控制线程间隔 p99 约 35.17 ms。
