状态：实现与预检已落盘，正式 attempt 为 0，400 条尚未采集。单进程多环境连续图像验收未通过，最终吞吐门槛也尚未完成；用户已授权每卡多个常驻单环境进程替代架构，正在实现并重新预检。见 [架构调整提案](architecture_decision.md)、[当前状态](implementation_status.json) 和 [实施记录](progress.md)。以下指标是验收条件，不是已取得的结果。

沿用实验规格 v1.3 和 `../../vib820_experiment_spec/config_v1_2.json`：X 独立均匀分布于 [-0.30,-0.14] m，Y 于 [0,0.40] m，yaw 于 [0,10]°，绕世界 +Z 正向旋转。回合内底盘平移、朝向和高度固定；头部低头 30°，腰、左臂维持原目标；右原始夹爪按下行按钮 0。物理 120 Hz，图像/状态/动作同步 30 Hz。相机分辨率、安装外参和视场不变：head 1280×720，overview 960×600，wrist_left / wrist_right / panel / front / lobby 均 640×480。

PCG64 seed=20261014。首次冻结 512 个候选，按既有顺序先生成全部 XY 再生成 yaw。若成功不足 400，从保存的随机数状态追加 512，最多 1024。按候选 ID 顺序取前 400 条成功，不能按并行完成顺序筛选。初始碰撞、IK 和动作失败保留，不改位置重试；基础设施中断允许同配置额外重试两次，attempt 独立编号。到上限仍不足则报告实际数量，不宣称完成。报告总尝试、失败分布、成功分布，明确成功筛选造成的分布变化。

## 2. 常驻 GPU 架构

两张 GPU 各一个常驻仿真进程，每进程多环境，初始化一次场景、机器人、相机和渲染资源。完整场景以 6 m 网格间隔复制，保存环境局部到世界变换，隔离跨环境碰撞；只保留一个全局环境光，避免过曝。每 GPU 一个物理步进循环，按名称映射批量设置 32 关节目标、读状态，各环境独立阶段/接触/按钮/终止状态。整轮结束后暂停、重置关节及速度、底盘锚点、按钮及灯，再开始下一轮；训练不包含复位帧。

按三种分辨率构建平铺渲染产品，每四个物理步同步采样，渲染时物理时间冻结。禁止旧帧、插帧、丢帧或降低采样频率。验证 CUDA 张量、GPU Dynamics 和 GPU broadphase 的实际状态，以及接触报告与碰撞查询；不得简化碰撞体或放宽阈值。比较 CPU/GPU 后端的正确性和吞吐，生产使用通过验收的较快者，即使 CPU 物理胜出仍保留 GPU 批量渲染与 NVENC，并如实记录。GPU 凸包与接触约束依据本机版本及 [Omni Physics 限制](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/107.2/dev_guide/guides/current_limitations.html) 核实。

保留现有 IK 求解器、种子、插值和限位；受限 CPU 工作池提前准备轨迹，主循环使用缓存并按实际接触切阶段，不同时更换控制算法。NVENC H.264 初始 p4/CQ18/无 B 帧/GOP30/YUV420，复用锁页缓冲区、有界队列；满时阻塞仿真，绝不丢帧。已有短编码测试不代表多路容量验收，不宣称零拷贝。初始每卡 2 环境；标定每卡 1/2/4/8，不沿用八个独立仿真进程。

### 本机实施适配，2026-10-15

多环境可见性预检发现相机能看到邻居房间。新增实验性 `isolated` 路径：物理仍按所有环境批量推进；每个 30 Hz 时刻冻结物理，依次只显示当前环境并激活其七个常驻原生相机产品，保留各自产品与缓冲区，全部环境完成后才推进下一物理步；不能据此假设渲染历史也已隔离。全局 Dome 独立于环境根节点，仅保留一份。两环境稳定静态诊断七路亮度最大差异约 1.37%；后续 20 次重置及 14 路 CPU/CUDA 像素一致性通过，但重复切换后的连续采样检查仍失败，左腕相对完整单环境参考均值差约 30%。因此该路径不能用于生产。保持原分辨率、安装外参、视场和完整碰撞几何。

原三组平铺渲染方案在本机 Isaac Sim 5.0 / Kit 107 中未通过投影验收：同一 tiled product 内不同内参的相机沿用首相机的投影，造成按钮位置与标定错位。统一尺寸 padding 也不能解决。实施改为按**分辨率、焦距、水平/垂直 aperture 与裁剪面完全一致**分组，共六个常驻平铺产品（双腕同组，head / overview / panel / front / lobby 各一组），每组跨环境批量 GPU 渲染。`homogeneous` 的部分历史预检通过实际投影、20 轮重置及逐回合完整录像检查，但环境互相可见的问题没有解决；最新 24 m 对称排列的 8 环境在第二次重置被灯环残留检查拒绝。没有可发布的多环境生产配置，也未宣称两倍加速。

入口默认 `individual` 保留每环境七个原生产品回退，生产 gate 必须与实际验证的渲染布局严格匹配；`padded` 仍禁止生产。这些实现均保留每卡一个常驻进程、多环境批量控制、锁页回读与 NVENC，原分辨率、视场、外参及 30 Hz 采样不变。

每次复位均用渲染器原生 `CameraParams` 投影矩阵核对七路内参，不能只检查手工计算的内参。固定 DLSS Quality，避免 Auto 随 atlas/画面尺寸切换质量；状态改变时在物理时间冻结期间使 DLSS 历史失效，再恢复质量模式，过渡帧不写入录像。FXAA/旧 NRD 参数路径已因本机兼容性和黑帧问题否决。逐帧检查七路空白图像，首个成功帧仍须通过解码后的真实亮灯检查。实测和失败诊断详见 [progress.md](progress.md)。

## 3. 数据、提交和导出

新增 Astribot 专用入口，不改变旧 Piper 格式。入口参数含成功目标、种子、候选上限、GPU 列表、每卡环境数和续采目录。原始目录独立，LeRobot 使用独立 0.6.1 环境、v3.0 格式及 Astribot robot_type。

`observation.state` 为 32 维实测关节角，`action` 为 32 维绝对关节目标，单位 rad；涵盖腰/躯干 4、头 2、双臂 14、夹爪连杆 12。冻结已验证模型 joint_names 顺序，按名称映射，不假定环境索引。另存 32 维速度、120 Hz 全量实测/目标、底盘和末端位姿、行程、力、灯、阶段。非末帧 action 使用下一个采样时刻（四物理步后）的实际目标；训练末帧重复前一帧目标，不能写撤回动作或以实测状态替代控制目标。

七路特征 `observation.images.<camera>` 保存原分辨率、内参、挂载外参、时间、步号和 epoch。物理触发后的首个采样帧必须在 panel 呈现亮灯，渲染延迟不合格；遮挡使用 panel 验证。任务固定 `Press the down hall-call button.`，不额外引入腰运动。

原始七路视频、轨迹和失败证据不可变。每条先写临时目录，视频关闭、全部帧解码及数值/物理审计通过后原子提交。续采仅跳过已验证提交，中断回合从头重跑。训练按帧截断，每 25 条导出分片，官方写入器及读取器验证，最终恰好 400 条。

## 4. 正确性与性能生产门槛

预检不计入正式 400 条：历史样本 001/002/003/005/010/020/024/035/040/050 对照；单环境、多环境、复用后原成功样本须通过独立审计，050 须仍被初始碰撞阻止。连续重置至少 20 轮，验证速度、接触、灯和渲染历史无残留。检查跨环境碰撞、相机、坐标和灯；同配置相对单环境平均亮度差 ≤5%。乱序完成、进程中断、重复提交、队列满、缺帧、损坏视频和续采均不得伪成功或重复数据。

正式全部数据通过物理/同步审计和七路完整解码。官方 LeRobot 读取器检查全部 400 条首/中/末帧、32 维字段及末帧 action padding；额外分层选 20 条做动作回放。

旧入口双卡四进程录四条完整七路视频作为同规格基线，不能用快照批次冒充。新每卡 1/2/4/8 各预热、至少两轮，分阶段记录启动/重置/IK/物理/渲染/回读/编码/写盘/审计/导出。每秒记录 GPU 活跃率/显存/编码利用率、CPU/可用 RAM、队列和磁盘写入。以验收成功完整回合/分钟选择；差异 <5% 取较少环境。显存 ≤80%，可用 RAM ≥32 GiB。目标提速 ≥3 倍，生产最低 ≥2 倍，否则继续优化。GPU 活跃率 ≥60% 为诊断目标，不制造无效负载。

生产前冻结后端、渲染、编码、控制和源码版本。故障允许降到已验收并发数并记录，不静默改物理或图像质量。
