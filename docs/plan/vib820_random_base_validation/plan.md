# 实施计划

## 1. 目标与冻结参数

验证现有「已知按钮位置 → IK → 关节位置控制 → 物理接触反馈」专家，在改变底盘初始位置后能否完成接近、按压、松开和返回。回合之间改变站位，回合内部底盘固定，不增加自主导航。

| 项目 | 本轮设定 |
| --- | --- |
| 场景 | 当前 VIB-820，按钮 ID `0`，单个下行外呼按钮 |
| 回合数 | 默认 30；允许在开始前指定 20–50；第 20 回合检查进度 |
| 名义底盘位置 | 世界坐标 X = -0.12 m，Y = 0.28 m；Z 沿用机器人加载配置 |
| 随机范围 | 用户指定 ΔX、ΔY 各自均匀分布于 [-0.20, +0.20] m，独立采样 |
| 实际坐标边界 | X ∈ [-0.32, 0.08] m；Y ∈ [0.08, 0.48] m |
| 坐标约定 | 本任务前后沿 X（+X 朝面板），左右沿 Y；+Z 向上 |
| 朝向 | 保持现有朝向，yaw = 0；本轮不随机旋转 |
| 随机种子 | 建议默认 `20261013`，保存 RNG 类型和库版本 |
| 控制与物理 | 保持现有控制速度、关节限制、120 Hz 物理步进、按钮弹簧与判据 |
| 图像 | 采用现有相机作排查用途；配置默认 10 Hz，精选视频可独立补录 |

采样区域是完整的 40 cm × 40 cm 正方形，不能先过滤为可达区域再声称完成此范围验证。每个站位重新求解 IK；不复用名义站位的关节轨迹。

## 2. P0：冻结基线，确认可复现

1. 读取 [taskmemory.md](taskmemory.md)，核对代码、配置、GPU 空闲情况和现有工作区修改。
2. 为批次保存 Git commit、dirty 状态、相关源文件及配置 SHA-256；如存在未提交修改，保存相关源码快照或补丁。不能只记 commit。
3. 在新输出目录重跑名义站位 1 次，用现有独立审计脚本核验。此回合属于冒烟验证，不计入随机批次。
4. 若名义站位也失败，先定位回归或环境问题；不能把问题归因于随机范围。

当前可用的名义站位命令如下。执行前确认 GPU 1 可用，输出目录必须不存在；时间戳仅作为目录名称。

```bash
cd /home/js/robot/VLA/PressB
source scripts/activate_local.sh
export CUDA_VISIBLE_DEVICES=0,1
batch_smoke="outputs/vib820_random_smoke_$(date +%Y%m%d_%H%M%S)"
python scripts/run_astribot_press.py --headless --gpu 1 \
  --config configs/astribot_vib820.json --buttons 0 --repeats 1 \
  --output "$batch_smoke"
python scripts/audit_astribot_press.py "$batch_smoke"
```

## 3. P1：实现采样清单和批次管理

建议新增 `scripts/run_vib820_random_base.py` 与 `scripts/summarize_vib820_random_base.py`。这两个脚本目前不存在，名称为实现建议。

- 先生成并落盘完整 `manifest.json`，包含批次 ID、样本 ID、种子、名义位置、偏移、最终 XYZ/yaw、数量、冻结配置和源码标识，再启动任何回合。
- 默认按预先生成的 30 个站位顺序运行。不可达、碰撞、超时都不能导致重新抽样。若在开始前选择 20 或 50，须写入批次清单。
- 每个样本从原始配置复制一份，只修改 `robot_base_x`、`robot_base_y`，保存回合配置。其他实验条件在同批次内保持一致。
- 第一版采用串行、每回合一个新仿真进程，调用现有 runner，`--buttons 0 --repeats 1`。降低状态残留风险，暂不追求并行吞吐量。
- 父进程保存启动时间、退出码、超时、标准输出与错误日志；即使子进程在产生 `report.json` 前崩溃，也要生成该样本的终态记录。
- 设置可配置超时，建议初值每回合 10 分钟；先用冒烟运行校准启动与运行耗时，再冻结本批次阈值。超时属于运行错误，不推断为不可达。
- 每完成一回合原子更新状态，支持继续未运行样本。重试保留独立 attempt ID；正式主统计使用各样本首次尝试，重试结果另报，禁止覆盖失败记录。

## 4. P2：站位、可达性和执行检查

### 初始站位

现有 runner 已同时设置机器人根变换与固定关节世界锚点；随机化必须保留这一行为。记录请求位置、实际初始根变换和被监测 base link 位姿，区分根节点与 link 的固定变换，不能直接比较不同坐标系的数值。底盘漂移以该回合的实际初始位姿为参考。

在运动前检查初始碰撞/重叠。明确场景查询的 collider 范围、过滤规则及允许的支撑接触；仅靠接触力阈值不能证明不存在初始穿插。若初始站位有禁止重叠，记录 `initial_collision` 并停止该回合运动，保留该样本。

### 可达性

本轮主要可达率定义为**关键位姿 IK 可达率**：工作起始位姿、接近位姿、目标按压位姿均通过 IK 残差和关节限位检查。尽可能在正式运动前完成并保存各阶段结果；即使初始碰撞，也可独立进行纯运动学求解。

现有 `report.reachability` 只保存部分解，不能作为全过程无碰撞证明。补全预检查结果与失败阶段记录。实际接近/按压/撤回中的轨迹 IK 失败另记 `path_ik_failed`，同时保留关键位姿 IK 结果。若另加离散轨迹预检查，应记录采样间隔，并单独报告，不能称为连续路径安全证明。

### 单回合流程

建立场景与站位 → 初始检查/关键位姿 IK → 初始化物理状态 → 合拢原始夹爪 → 工作起始位姿 → 接近 → 按压 → 撤回 → 返回 → 复位检查 → 独立审计。

- 保留现有按钮的真实刚体接触、弹簧回弹和灯光锁存逻辑。
- 每回合重新初始化关节、速度、按钮行程、灯光、接触累计和轨迹缓存。
- 发生禁止碰撞立即停止当前回合；保存接触对象、发生阶段、步号、仿真时间和力估计。
- 保存失败前的部分轨迹；若失败发生得太早没有轨迹，明确标记缺失原因，不填零。
- 为审计不完整记录增加容错封装，区分“物理条件不通过”和“数据缺失无法审计”。不能用审计脚本退出非零统一解释为碰撞。

## 5. P3：执行 20–50 回合并汇总

默认跑满预先声明的 30 回合，第 20 回合生成中期报告。单个任务失败不终止整个批次；GPU/仿真基础设施持续故障或监测机制失效时暂停，保留已完成和待执行清单，修复后按原站位继续。

如需扩充到最多 50 回合，预先声明新增数量，按已记录的 RNG 状态追加，保持前 30 个样本不变。若改变随机范围、物理参数或控制器，则另建批次，不混合计算成功率。

按 [metrics.md](metrics.md) 输出精确分子/分母、缺失覆盖率、失败原因和 XY 站位散点图。保留全部失败材料；至少选取一个成功回合及各已出现失败类型的代表快照，能录制时提供视频。

建议后续扩大专家数据采集的工程门槛：关键位姿可达率 ≥90%、尝试按压成功率 ≥90%、无已知禁止碰撞，且预检查和碰撞监测无未知缺口。门槛是本计划建议，不是已有结果或用户指定指标。未达门槛也应完成本轮报告，定位可用区域与主要失败原因；不能通过删掉困难站位来达标。

## 6. 输出组织与完成条件

```text
outputs/vib820_random_base/<batch_id>/
  manifest.json                # 采样清单、实验定义与版本
  sources/                     # 相关源码快照/补丁与哈希
  episodes/<sample_id>/
    config.json
    attempts/0001/
      run/                     # 交给 runner 创建的新目录
        report.json
        trajectory.npz         # 进入记录阶段后产生，可为部分轨迹
        independent_audit.json # 数据足够时执行；不足则写审计不可用原因
      stdout.log
      stderr.log
      result.json              # 批次管理器保证产生的终态记录
  summary.csv                  # 每个计划样本一行，不仅列成功回合
  summary.json                 # 汇总计数、比例与未知项
  station_results.png          # XY 分布、失败类别、名义站位和边界
  report.md                    # 从 results_template.md 填写
```

不要提前创建 runner 的 `run/` 目录，其入口使用 `exist_ok=False`。`outputs/` 已被 Git 忽略，须在报告中记载实际路径和归档方式；导出的场景引用仓库内机器人/纹理资产，单独复制 `scene.usda` 不等于可移植场景包。

完成标准：20–50 个唯一随机样本获得可追溯结果；预定批次若未跑完，明确标记中断，不宣称完整完成；三类指标与覆盖率齐全，失败可定位，给出是否进入下一阶段的结论，并逐项填写 [assertlist.md](assertlist.md)。

后续专家数据阶段再增加机器人头部/腕部相机观测、观测与动作对齐、训练数据格式及视觉随机化。当前场景真值可供专家控制器使用，但不能混入未来视觉策略的输入。
