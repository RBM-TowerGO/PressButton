## 1. 目标与范围

使用现实中采集并人工清洗的按键示范，对 VLA 做真机专用监督微调。模型读取头部、右腕 RGB 图像及实测状态，输出右臂 7 关节＋夹爪 1 维＋头部 2 关节，共 10 维控制目标。头部由模型输出，目标是维持示范姿态。

第一版先打通数据、训练、离线验证与基础真机执行链路。主动转头、多头部姿态恢复、新增采集任务、仿真与真机混合训练、强化残差训练不属于本版实施范围。基础策略稳定后再单独规划强化残差。

## 3. 数据与模型接口

### 3.1 固定设计

- 图像：头部、右腕两路 RGB；核实 HDF5 头部图像对应的实际相机，不能直接假定是任意 head 话题。保留原始分辨率信息，训练和部署共享缩放与颜色处理。
- 状态：右臂 7＋夹爪 1＋头部 2 的实测位置，顺序固定。夹爪实测值保留连续反馈，不因为动作二值化而二值化状态。
- 动作：右臂和头部使用绝对关节目标（rad）；夹爪采用以下审计后的编码。不得将未来实测状态替代控制目标，不输出仿真的 32 维展开动作。
- 头部：使用记录的控制目标监督，不用实测均值替换；头部输出维度保留在模型中。部署时如另加固定姿态覆盖，必须单独记录，不能把覆盖后的结果视为模型学会保持。
- 归一化：只使用训练集统计，状态和动作分别处理；显式处理常量维度，并保证归一化／反归一化数值有限、可往返。

### 3.2 夹爪编码：必须先审计，再定案

保存的 SDK 原始单位是 0～100 闭合刻度，0 全开、100 全闭。它不是仿真夹爪弧度，也不是经标定的物理宽度。`g/100` 是刻度归一化，不是物理标定。

先统计全量夹爪 **command** 的唯一值、分位数、每条范围、切换次数，以及中间目标的持续时间；实测 state 单独统计。不能仅凭实测值处于中间位置，就认定示范存在中间开度目标。

| 审计结果 | 本版处理方向 |
|---|---|
| 只有全开／全闭目标 | 优先采用动作 `{0,1}`，执行映射回 SDK `{0,100}` |
| 存在有意保持的中间目标 | 保留连续闭合刻度，训练可归一化至 `[0,1]` |
| 只有单一固定目标 | 明确标记常量维度，不能声称学会了开合切换 |
| 存在端点附近噪声或疑似过渡目标 | 输出分布及对应片段证据，再确定容差和映射，不预先按 50 强行二值化 |

若采用二值动作，第一版仍保留现有连续动作模型的单个夹爪输出维度，不另增分类头；在编码定案时一并固定归一化和部署解码阈值，并测试往返。阈值前的原始预测和实际下发值均需记录。若输出抖动，再评估滞回策略并升级契约。当前尚未确认实际目标分布，因此本文不把二值化标为已决定或已实现。

### 3.3 时序：正式训练前的阻塞项

审核后数据组合指令与主时间的最大绝对偏差约 13.079 ms，实测状态约 3.975 ms，右腕图像约 30.532 ms；这些偏差不能证明曝光时刻、指令生成时刻和执行时刻相同。

需核实官方导出器的统一时钟与 command 时间戳重建规则。原始消息的 command header 与 state header 不在可直接比较的时间域，禁止直接跨域最近邻匹配。优先读取转换器实现或配置，并用可追溯原始消息验证；证据不足时明确保留阻塞，不以“时间接近”替代证明。

目标沿用 30 Hz、未来 7 步预测，但须根据核查结果确定重采样网格、指令保持／选取方法、图像与状态最大可接受时间偏差、过期样本排除规则、末尾不足 horizon 的 padding 与 mask。不得机械地把同一行或下一行 command 当成标签。所有规则及被排除帧数须写入数据契约；若现有记录无法支持，先补齐同步记录证据，再正式转换训练。

各阶段按依赖顺序推进。准备和代码工作可开展；正式训练必须在数据契约冻结、转换验收及训练冒烟通过后启动。

### P0：锁定数据与补齐契约

- [ ] 锁定 96 条审核后文件与哈希、审核版本；原始及审核后 HDF5 保持只读用途。
- [ ] 完成夹爪 command／state 分布报告，确定动作编码、单位、归一化和部署解码。
- [ ] 补齐图像来源、颜色顺序、时间域和目标时间偏移证据；明确无法补证的限制。
- [ ] 输出版本化 `data_contract.json`：特征名、维度顺序、单位、时序、常量维度、数据来源及排除规则。

验收：10 维中每一维、每个动作步都能解释来源和控制含义；时序或编码未定时不得标记 `model_ready=true`。

### P1：真机 LeRobot 转换与划分

- [ ] 新增真机 HDF5 适配器，输出独立目录 `data/astribot_s1b_real_joint10_v1/`；不覆盖仿真数据或审核结果。
- [ ] 优先沿用项目已有 LeRobot v3.0 格式与固定版本依赖；输出两路图像、`observation.state` 10 维、`action` 10 维、任务描述及来源追溯信息。
- [ ] 保存源 episode／帧和目标时间映射，以及重采样、排除和 padding 记录；说明单步 action 与训练时 7 步窗口的构造关系，避免双重移位。
- [ ] 按完整轨迹划分 train／validation，优先按连续采集时段或场景分组。目标约 80／16 条，组边界优先于精确条数；固定 seed=42 并保存实际清单。禁止随机拆帧，验证集不参与归一化。
- [ ] 使用官方读取器回读；核对全部数值和边界映射，抽查每条首／中／末帧双路图像及动作窗口。

验收：无 NaN／Inf、跨 episode 窗口或数据集泄漏；输出帧数与重采样／排除清单一致，重复运行可追溯。96 条不意味着转换后必须仍为 23,039 帧。

### P2：10 维模型及训练入口

- [ ] 定位并版本锁定实际 VLA-JEPA 训练代码、依赖和运行硬件；本仓库的导出器与模型元数据不等于完整训练入口。
- [ ] 建立真机专用 state_dim=10、action_dim=10 配置，复用两路视觉输入；更新 dataset reader、归一化和输出 schema。
- [ ] 优先以已有仿真微调 step 8000 为迁移基线；确认权重实际可用并记录哈希，缺失时不得静默换权重。迁移兼容的内部权重，重新初始化与新坐标接口直接相关的状态输入／动作输入输出层，不沿用旧夹爪统计量或优化器状态。
- [ ] 新建训练运行目录，固定随机种子，保存数据／代码／配置指纹、加载及重置参数清单。
- [ ] 先完成单批次前向、反向、保存恢复、反归一化，再用少量完整轨迹做过拟合检查。
- [ ] 根据实际显存与冒烟结果锁定 batch、梯度累积、分组学习率、验证间隔和训练预算，写入正式运行配置。不要直接照搬原 400 条仿真数据的总步数。

验收：输出形状为 batch×7×10；loss／梯度有限；常量头部目标可正确还原；缺失或不兼容权重有明确报告；恢复训练使用同一数据契约。

### P3：正式微调与离线评估

- [ ] 启动真机数据监督微调，按固定验证清单保存和比较 checkpoint。
- [ ] 分维报告手臂与头部误差（rad／度）、夹爪误差或二值正确率，以及不同预测步长的误差；不能只汇报混合单位总 loss。
- [ ] 检查头部目标漂移、预测范围、动作连续性和夹爪输出；夹爪若无状态切换，明确其评估局限。
- [ ] 与保持当前状态／训练集常量目标等简单基线比较；按验证结果选权重，保留最终权重及完整配置。

验收：生成可复现离线报告和选模依据。离线误差降低不等于真机按键成功；96 条足够启动实验，不预先保证泛化或成功率。

### P4：真机推理适配与分阶段验证

- [ ] 使用已核验的部件话题构造实测 state10；不把实时全身状态盲当成 HDF5 的 25 维布局。
- [ ] 将模型目标映射到右臂、右夹爪和头部 SDK 绝对目标接口，落实夹爪解码、关节限位、动作变化约束及异常退出处理。
- [ ] 记录观察时间、推理起止、动作目标时间和发送时间；按测得延迟确定 7 步动作的执行方式，不能直接复用仿真暂停推理假设。
- [ ] 先做离线回放和只预测不下发的影子模式，再从示范附近姿态开展受控闭环；记录急停／人工中止、按键成功和失败原因。
- [ ] 汇报模型原始头部输出、实际下发目标和实测保持误差；评估前锁定试次安排与成功判据，实际计数后汇报成功率。

验收：模型、数据、推理代码版本一一对应；能够追溯每次实际命令。工程链路通过与任务效果有效分别报告。本计划文档的建立不代表已启动机器人运动。
