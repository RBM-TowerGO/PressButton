# 真机数据转换规则与补充审计 v1（2026-10-25）

用户已确认示范只考虑全开／全闭，因此夹爪动作采用二值化。本文冻结第一版**记录时间监督**规则；机器可读定义见 [data_contract.json](data_contract.json)。转换器和训练尚未实现，`model_ready=false`。这些规则不声称恢复了传感器曝光时间或实际命令执行时间。

## 1. 全量夹爪检查

重新核验全部 96 个文件 SHA-256，通过；共 23,039 帧。

| 原始控制目标 | 帧数 |
|---|---:|
| 正好 0（全开） | 5,696 |
| 正好 100（全闭） | 16,952 |
| 中间目标 | 391（约 1.70%） |

目标共 366 个不同数值。94 条轨迹含中间目标，共 177 个连续中间片段，其中 173 个连同前后端点单调；不能笼统称所有中间值都是严格单调过渡。最长片段在 `episode_000004` 的 `[8,37)`，29 帧、首末帧间 0.9303 秒，前后均为 100，内部约 92.81～99.31，二值化后仍保持闭合。其余 3 个非单调片段位于 episode 4、12、28，前后端点均为 100→0。

按 `command < 50 → 0`、`command >= 50 → 1`，得到开 5,887 帧、闭 17,152 帧；各轨迹内总计 176 次切换。该阈值是基于用户明确的二值任务语义选择的量化规则，不是从记录中恢复到的按钮触发瞬间。保留中间值及源帧映射，不删除过渡帧，不把切换时刻提前到整个过渡段开头。

实测 state 仍连续保留，范围约 -1.8710～97.9095；不截断反馈，也不改成 0/1。动作二值维度直接用 0/1，不应用统计标准化；模型仍输出一个连续维度，执行端反归一化后 `<0.5 → SDK 0`，`>=0.5 → SDK 100`。非有限预测拒绝下发。原始 command 若非有限或超出 [0,100]，转换校验失败，不能静默截断。

## 2. 新增时序证据

使用之前已用官方工具离线转换的原始 MCAP 探针 `elevator1_2026_10_25-17_32_50_2`，165 帧；它不是审核后 96 条中的一条。

逐帧匹配发现以下时间字段与对应 MCAP `log_time` 精确一致：

| HDF5 字段 | 探针中匹配的原始话题 |
|---|---|
| `time`、head RGB timestamp | `/astribot_camera/head_rgbd/color_compress/compressed` |
| right RGB timestamp | `/astribot_camera/right_wrist_rgbd/color_compress/compressed` |
| `joints_dict/state_timestamp` | `/astribot_chassis/joint_space_states` |
| `joints_dict/command_timestamp` | `/astribot_arm_left/joint_space_command` |

原始探针中 log_time 与 publish_time 相等，仅凭数值匹配不能区分二者。因此另外复制 MCAP，将**全部 log_time 加 10 秒**，publish_time、消息 header 和序列化数据保持不变，再用 S1B 上同一个官方转换器离线转换。上述全部时间字段逐帧恰好加 10 秒；关节 state／command 和两路图像字节完全不变。此受控实验确认该探针时间字段依赖记录时间，不是将各部件小秒值 header 重建成 epoch。

按各部件 MCAP log_time 距离 head 记录时间最近的命令，右臂、右夹爪、头部值均与探针 HDF5 的 165 行逐行完全相同。右臂对应消息时间相对 head 为 -6.061～+5.527 ms。该结果支持记录时间最近邻选择，但常量目标可能对应多个相同值消息，因此不把数值匹配等同于唯一定位所有消息。

公共 command timestamp 匹配的是左臂，公共 state timestamp 匹配底盘，**不能据此给右臂／夹爪／头部赋予独立精确时间**。现有头部相机映射还得到官方安装头文件 `mcap_to_hdf5.h` 的具名话题佐证。

未找到安装环境中的转换器 `.cpp` 源码；保留了头文件、日志和二进制反汇编供后续核查，反汇编未作为已完成源码证明。96 条示范缺少同帧原始 MCAP，无法补回丢失的各部件时间戳；不伪造这一证据。

## 3. 第一版转换的确定规则

1. **坐标与图像**：state、command 取已核验的 25 维布局列 `[15:25]`；两路 JPEG 解码为 RGB。保留头部与右腕图像，动作中第 7 列（零起始）按上述规则二值化。
2. **统一时间语义**：使用 HDF5 `time` 作为已对齐记录行的参考时刻。公共 state／command timestamp 只用于质量筛查，不重新用它给 10 维目标打时间标签。这是录制时间代理，不是执行时间。
3. **30 Hz 网格**：相对时间 `time-time[0]` 上建立 `k/30` 网格，止于源数据末时刻。观察取不晚于网格时刻的最后一个源行；不插值图像、夹爪类别或关节目标。源行最多保持 `2/30` 秒。使用相对时间避免 epoch 浮点误差影响索引。
4. **目标偏移**：观察 `t` 预测 `t+1/30 ... t+7/30`。每个目标时刻选择不晚于它的最后一个源行 command，禁止取未来实测 state。LeRobot 的单步 `action[k]` 存 `t[k]+1/30` 对应目标，训练读取连续 7 个 action；读取器不得再整体后移一帧。
5. **边界与 mask**：无下一步目标的最后网格行不写入训练数据；其余行可保存单步 action，但仅完整 7 步有效窗口可作为训练 anchor。尾部不足窗口不重复填充。超过 `2/30` 秒的源间隔切分连续段；跨段、跨轨迹、跨失效行窗口排除，保存原因和索引。
6. **筛查阈值**：相对源行 `time` 的绝对偏差限制为 state 10 ms、公共 command 20 ms、右腕图像 40 ms、head 图像 0.001 ms。它们是本版工程筛查门槛，不是已标定的传感器延迟界限；不满足则排除该行及受影响窗口，不放宽阈值掩盖异常。
7. **归一化**：状态全部 10 维使用训练集 mean/std，标准差下限 `1e-6`（原生单位）；动作只对手臂和头部拟合 mean/std，同样下限 `1e-6` rad；夹爪动作保持 0/1。精确常量头部动作归一化为 0，反归一化恢复示范控制目标。保存全部统计与常量维度标记。
8. **追溯**：为每个网格行和每个未来目标保存源 episode、源行、源时间、网格时间、原始夹爪目标及二值目标。转换前后均不改原始 HDF5。

原 HDF5 内部对齐本身可能选中了略晚于 head 的消息，网格再取过去行并不能消除这种情况。本版接受并明确记录这个数据来源限制；不得把数据宣称为严格因果传感器同步。正式真机部署仍须测在线延迟并验证动作调度。

## 4. 规则干跑及后续工作

在全部 96 条上进行数值／时间索引干跑，得到 22,850 个网格行、22,178 个完整 7 步 anchor。按上述阈值没有失效网格行，没有额外排除完整窗口；每条末尾 7 个网格时刻不作为 anchor。若按第 5 条省略每条最后一个无单步目标的行，预计写入 22,754 个单步记录。未编码视频或实际写入 LeRobot，这些计数不是已完成导出结果。

后续实施转换器时必须测试：阈值 50／0.5 的边界、非有限值、相对时间索引、长间隔和轨迹边界、首末目标偏移、常量维度往返、训练读取器无双重偏移，以及官方 LeRobot 回读。此处的动作与时序规则已可用于实现第一版离线数据转换；实际训练准备完成后才能更新 `model_ready`。
