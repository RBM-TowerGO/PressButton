## 执行顺序与预算含义

1. 核验代码、模型、环境和资源，保存完整命令及源码身份。
2. 独立启动本次推理服务，等待健康检查通过。
3. 采集完整训练回合，持续保存逐回合报告、请求、metrics、checkpoint 和 replay。
4. 首次达到 2000 条后集中补齐更新；随后在回合结束后按累计数据量补充更新。
5. replay 达到 100k 后结束训练，检查更新数、维数和数据完整性。
6. 使用最终 checkpoint 运行 40 秒 val-40；检查评估没有改变训练文件，并与历史 23/40 基线逐场景配对统计。
7. 保存结果并关闭本次服务；基础设施或非有限数值错误停止，保留证据，不自动调参或无条件重启。

## 监测与结果判定

每个回合统计成功/失败/超时、累计 transition、成功终止 transition 数、成功回合内全部 transition 数、最近 20 回合成功率和回合长度。
训练成功率含探索，不代替验证指标；重点观察首次成功何时出现，不能仅凭 replay 足够大判断信号充足。
保存 Critic/Actor loss、Q 预测/目标、梯度、alpha、残差幅度及耗时。更新数增长和有限 loss 只代表运行正常，不代表学会。

本次不设平台期早停，不因成功暂少自动修改奖励；非有限数值、服务故障、物理协议错误按现有异常路径停止。
训练完成后报告 val-40 成功数、相对历史基座的改善/退步场景和失败分类。历史基线不同机器/运行批次，配对结果仅为参考；未重跑同期基座，不声称严格受控显著提升。
如果成功为零或表现退化，原样报告，不以工程验收替代学习效果。
