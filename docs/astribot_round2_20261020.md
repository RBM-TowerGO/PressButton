## 启动修复与效率验证

- 修正策略服务脚本的旧绝对路径；创建独立推理覆盖环境，不修改 Isaac 环境的依赖。
- 修复塑形启用时缺失 `row["distance"]` 的错误，记录执行前距离。
- 增加推理、控制、渲染分阶段计时。相关 50 项 CPU 测试通过，见 `logs/round2-contract-tests.log`。
- 最终相关检查为 52 passed；含监督文档更新与配对统计的契约测试。渲染专项另为 7 passed / 9 skipped，实际 GPU 相机链路由冒烟覆盖。
- 增加选择原生相机产品的选项，默认保留旧行为。两路输入均保留原分辨率、投影、位姿同步与物理冻结检查。
- GPU 1 运行共享冻结 VLA 推理，GPU 0 运行两个独立单环境进程。每个种子有独立 SAC、replay 和输出目录，分别做 val-40；没有使用未验收的同进程多环境相机隔离。
- SAC 小网络保留单线程 CPU 更新，避免小矩阵的设备传输；两张 GPU 用于相机/物理和大型冻结模型。
- 暖身阶段也按回合保存 learner/replay，避免首次更新前无恢复点。监督进程每 30 秒更新文档和资源采样，训练完成自动执行 val-40；两组均结束后释放本次基座服务。

### 单进程实测

下表来自相同 seed、候选 277 的 6 s 仿真回合（26 transitions）；不含启动和 learner 更新，短测不能作为长跑加速比。

| 物理 / 相机 | 回合耗时 | 采样吞吐 | 控制 / 推理 / 渲染 |
|---|---:|---:|---|
| GPU / 七路 | 13.30 s | 1.96 transition/s | 7.60 / 3.09 / 2.54 s |
| GPU / 两路 | 10.97 s | 2.37 transition/s | 7.49 / 2.39 / 1.02 s |
| CPU / 两路（未采用） | 5.43 s | 4.78 transition/s | 1.95 / 2.41 / 1.01 s |

两路与七路的初始图像 8-bit MAE 为 head 2.24、right-wrist 2.59；分辨率相同。候选 95 在 GPU/七路、GPU/两路均完成真实物理按压（分别 1.040 / 1.297 mm，0.322 / 0.363 N，灯亮，0 次异常接触）。CPU/两路虽然更快，该场景超时；另一个候选 304 能成功。为保持训练物理后端与既有评估一致，本轮**不采用 CPU 物理**。

正式评估恢复原生七路相机和原 GPU 状态回读，保持历史 val-40 协议。仅训练阶段减少非策略相机产品。

正式双进程的首个暖身回合各完成 172 transitions：合计 344 条、采样时间窗 104.05 s、合计采样吞吐 3.31 transition/s。这个数排除初始化和梯度更新，仅作为启动阶段吞吐；长跑平均值以自动进度为准。证据：`logs/round2-concurrent-initial-throughput.json`。

另测过合并 GPU 状态回读，候选 95 从成功变为超时，且控制耗时没有改善；该实现已撤回，正式训练保留原回读顺序。短测/接触测试均保存了逐回合报告，位于 `outputs/astribot_online_rl/round2_*`。

## 2026-10-20 17:49 检查与恢复

17:49 检查发现两组均已停止：seed 20261021 在 16:26 因腕相机位姿检查失败，保留 20,175 transitions / 20,131 updates / 159 个完整回合；seed 20261022 在 14:01 同类中断，保留 666 transitions，尚无梯度更新。两组均未进入 val 评估。相机误差分别为 0.03317 和 0.000506（矩阵一致性误差，不能直接解释为米）。

恢复措施：

- 保留原 `1e-4` 位姿检查阈值；同步 PhysX/Fabric 与 CUDA 后捕获。位姿不符的帧会丢弃，在物理时间和关节状态保持不变时最多捕获三次，每次均重新验证；连续失败仍停止。
- 记录原始误差、相机矩阵、上一有效位姿误差、关节状态与恢复标记到 `run/shared/pose_sync_retries.jsonl`，供确认是否为暂时的渲染/物理同步问题。
- 修正基础设施中断被写成物理 timeout 的报告分类。原始报告保存在 `report.before_infrastructure_classification.json`；中断回合不进入训练成功率分母。异常前已合法提交的 transition 保留。
- 恢复前把 checkpoint、replay、状态、日志和异常归档到各目录 `recovery/`，附 SHA-256。actor、optimizer、RNG 和 replay 原样加载，超参数与预算不变。
- 对连续捕获仍失败的同类训练异常，监督程序最多重启三次仿真进程并从保存点恢复；其他错误直接停止。评估不通过这种方式跳过失败场景。
- 进度监控按恢复/接管后新增的 transitions 估算速率，避免把恢复前累计数据除以很短的重启时间。监控进程的接管不会重启工作进程或修改学习状态。

54 项相关测试通过，真实 GPU 冒烟完成 26 条 transition 和 8 次更新。17:56 左右两组从保存点恢复；主种子的候选 75 重新执行成功。后续计数、错误与结果以本页自动进度和独立种子页为准；尚无第二轮验证集效果结论。
