# SDK 躯干示范姿态恢复研究（2026-10-28）

结论：SDK 提供显式躯干关节运动与周期保持接口，可以在模型推理执行之前恢复示范躯干姿态，在推理期间保持固定躯干目标；不需要修改10维模型或重新训练。当前实现尚未接入，未进行运动实验。

## 已核对的SDK行为

本目录 astribot_client.py、astribot_interface.py 是2026-10-28从 S1B 的 /home/astribot/astribot_sdk_aarch64/astribot_sdk/core/astribot_api/ 只读复制的当前代码。未构造 Astribot 客户端。

- `move_to_home()`（client第554行）明确将躯干设置为 `[0.29,-0.58,0.29,0]`，同时改变双臂、夹爪、头部。这与已有推理记录的躯干约 `[0.285,-0.571,0.284,0.009]` 接近，但没有调用记录能证明本次姿态一定由该函数产生。
- 两批示范的实际控制目标中位数分别约 `[0.595157,-1.193124,0.597664,-0.000183]`、`[0.593475,-1.192108,0.598070,-0.000301]`，接近 `[0.6,-1.2,0.6,0]`。目标来自 HDF5 `joints_dict/joints_position_command[:,3:7]`，不是实测角度中位数。示范目标有小幅变化，因此不存在能精确重现每帧的一组常量。
- `move_joints_position(names, commands, duration, use_wbc=False, add_default_torso=False)`（client第493行）接受具名 `astribot_torso` 的4维目标，包装器转发到底层 `move_to_joint_position`。可用于开始前的有限时长姿态过渡。Python源码不足以证明底层原生调用的中断时延或完整路径避障，须实测/进一步核对。
- `set_joints_position(..., control_way='filter', use_wbc=False, add_default_torso=False)`（client第704行）可在现有250Hz周期中显式同时发送躯干4维和原模型控制的右臂7/夹爪1/头部2；interface第568行仅检查control_way并转发到底层。
- `get_joints_position_limit`、`get_joints_velocity_limit`、`get_current_joints_position`、`get_current_joints_velocity` 可用于运行时限制核对及实际到位验证。
- `move_joints_position` 在未显式传躯干且add_default_torso=True时，补入的是 `get_desired_joints_position([torso])` 当前目标，不是示范姿态。周期set接口的此参数由原生库处理，不能从Python包装器推断更多；不应靠这个布尔参数恢复采集高度。

## 建议接入流程

按S并取得控制权 → 独立ALIGNING_TORSO阶段 → 实测到位、稳定 → 更新baseline及观测时间门槛 → 重新采图/推理 → 开始原模型执行。

1. 为躯干单独保存参考姿态及数据来源（优先选已审核成功示范的真实稳定目标，而非无来源手填值），不修改模型10维action/state契约。可用约[0.6,-1.2,0.6,0]作分析比较，不把近似数直接作为未验证的运动指令。
2. 在安全起始手臂姿态、尚未接触面板时完成躯干过渡。躯干移动会移动双臂/头部基座；“保持手臂关节角”不等于“保持夹爪空间位置”，不能在夹爪已贴面板时直接下降10cm。
3. 查询实际躯干限位、速度，验证参考及过渡，持续监控急停、驱动状态、控制权、状态新鲜度、停止请求和运动超时。原生离线运动调用的可中断性未核实前，不能直接把长阻塞调用塞入现有控制线程。另一实现选项是独立、限速限加速度的250Hz过渡阶段。
4. 用躯干实测位置与速度判定到位，考虑示范中目标与实测存在静态偏差，误差阈值需按数据及现场验证设置，不能直接照搬未控制漂移0.003rad。
5. 过渡完成后再更新时间门槛并获取新图像/状态。丢弃姿态变化前的预测。当前ControlSession.start已在初始化后设置accept_observations_after_ns，可扩展此结构；需避免提前启动首预测1秒时限。
6. 推理期间把固定躯干目标与原10维控制目标合并为SDK命令，同时保留模型契约不变。SDK命令的名称与维度必须显式对应，不能直接改全局PARTS导致10维拆分失效。
7. 躯干成为受控部件后，必须从“未控制部件漂移”逻辑移出，增加单独躯干跟踪和停止反馈检查；不能仅更新baseline掩盖后续误差。停止/释放仍覆盖整个机器人。
8. Shadow模式仅计算/报告姿态差异，不得控制躯干。离线验证覆盖消息维度、限位拒绝、过渡故障/停止、到位判定、旧观测拒绝、固定保持目标；随后才进行操作者在场的短真机对照。

## 实验目标

保持checkpoint4500、面板/底盘站位、执行策略及现有限位不变，仅对齐采集躯干姿态和一致的初始姿态。比较末端相对按钮的垂直偏差及腕部跟踪，检验此前约9.9cm肩基座差异是否为主要原因。不要直接对模型末端加-10cm偏置，也不要同时扩大关节限位。

本研究不改变控制程序、不发送动作。已有分析数据见 outputs/s1b_high_gripper_analysis/。
