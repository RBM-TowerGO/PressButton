**结论**

建议先实现“示范上下文驱动的 Qwen 视觉闭环”：把成功演示整理为动作前后双视角图片、命令、阶段和结果参考；每轮结合实时观测重新决定下一步，由已有机器人服务执行有限动作。先验证无需训练的上下文学习，再决定是否训练 VLA。单条示范足以做这个可行性实验，不能据此保证稳定泛化或训练出可靠通用策略。

**这次演示实际提供了什么**

会话约 211.86 秒，10 个操作：1 次夹爪、1 次头部、8 次 Cartesian 平移。共 42 张 JPEG、21 份原始深度：initial 加 20 个动作边界。20 个 before/after 均 complete，操作边界三路相机 source 时间最大差约 49.29 ms；这不等于图像和机器人状态已同步。

画面中的目标为外呼“向下”箭头按钮，不是楼层数字按钮。流程由图像和命令推断如下；阶段名不是原始人工标注。

| 操作 | 原始命令 | 阶段解释 |
|---|---|---|
| 1 | C，夹爪目标 100 | 准备夹爪；首次发送成功不是夹爪已闭合 |
| 2 | 头部 yaw/pitch = 0/30° | 调整观察角度 |
| 3 | XYZ = 0/0/+300 mm | 抬手，后续又下调，不能当作最优路径 |
| 4 | 0/+100/−100 | 粗定位 |
| 5 | 0/−2/−50 | 高度修正 |
| 6 | 0/−50/0 | 横向对齐 |
| 7 | +45/+20/0 | 接近，同时修正横向 |
| 8 | 0/−10/0 | 近距离横向微调 |
| 9 | +15/0/0 | 接触/按压尝试 |
| 10 | −100/0/0 | 撤回 |

坐标为 chassis：+X 前、+Y 机器人左、+Z 上。Agent 的 right_mm 对应 −deltaY；位移参数是 mm，命令位姿中的位置是 m，姿态是 xyzw。全程命令净增量为 X=−40、Y=+58、Z=+150 mm；最后并未回到完整初始位姿。

记录局限：

- `session.json` 的 `recording_complete=false`，原因是 final 采集 connection refused。不能改成完整记录；最后可用观测是 `000010/after`。
- `operation.json` 保存的是 start/target **command pose**，不是实测末端轨迹。Recorder 没有记录逐时刻关节、力矩或实测位姿。250 Hz 是控制发送频率，不是这份数据的图像/状态采样频率。
- `completed` 主要表示插值指令发送结束，不是接触、到位或按钮触发。
- 用户报告任务成功。审阅第 9 步前后可见按钮边缘亮环变化，但画面有反光和遮挡，缺少连续触发记录与外部信号。数据标签应保留 `operator_reported_success=true`、`machine_verified_success=null`，不能把视觉候选证据升级为自动验证。
- 操作间人工观察/输入等待不能自动变成需要模仿的接触停留时长。

特别注意两个容易被忽略的差异：

1. **控制调用路径不能当作相同。** 当前键盘代码在 C 后保留非空 gripper_target，平移进入 `set_different_type_command`；Agent 的发送线程传入 None，走 `set_cartesian_pose`。头部操作另走 `set_joints_position`。这次日志没有保存运行代码版本，因此“该次一定使用上述路径”只能是当前代码推断。需要记录代码版本、SDK版本、执行模式，并实测核对，不能仅凭共用循环就宣称等价。不要为模仿示范擅自切换 Agent 到 mixed 模式。
2. **示范按压与旧 press 语义不同。** 第 7 步先前伸45 mm且保留位置，第 8 步在近处横向调节，第 9 步再前伸15 mm，第 10 步后退100 mm。旧 press 是一次伸出后立即回到本次起点，无法表达这个完整流程。第9步前固定点深度161.04 mm，旧公式只得11.04 mm；人下发的是15 mm。这个差异不能直接解释为“还需额外4 mm”，因为固定点未必测按钮接触面，且命令/实测和相机/TCP关系尚不完备。

当前 `--replay` 只接受 Agent 观测目录中的 `manifest.json`，键盘数据只有 `metadata.json/capture.json`。不能把此次键盘文件夹直接传给它。需独立的示范审阅/决策回放适配层，保留 measured state 缺失，不得用 command pose 冒充实测状态绕过 schema。

**推荐实现方式**

数据流可以固定为：

```text
历史示范 → 整理阶段/前后图/命令/证据 → 示范参考库
                                         ↓
实时 head + wrist + depth + 实测state → Qwen阶段判断与单步建议
                                         ↓
                              参数/阶段/观测有效性校验
                                         ↓
                           已有SDK执行器 → 新观测与结果
                                         └────────→ 下一轮
```

第一版只有一个示范，无需向量数据库。保留完整流程的简短文字，每轮发送当前双视角、匹配阶段前后图片和必要的相邻阶段图片；避免把42张图片全部重复发送。示范图片标记 demo/step/before/after，当前图片标记 live/observation_id，并明确相机名称。

建议阶段为 prepare → coarse_align → approach → fine_align → press → verify → retract。状态推进依据当前可见条件和执行反馈，不能只用示范步号自增。若模型判断当前状态接近第6步，即使从第1步启动，也无需重复已经满足的准备动作。

Qwen负责选阶段、定位目标、决定修正方向/幅度和解释证据；执行器负责插值、坐标换算、限值和停止。高频发送维持在机器人侧，不能让大模型生成250 Hz关节序列。

示范用于提供动作与视觉变化的方向/尺度先验，实时观测用于修正。若要使用视觉误差到位移的线性映射，可用本轮已知小位移和目标像素变化估计局部雅可比；但应限定头部/腕部姿态、深度与局部区域，不能从一条示范拟合全局pixel-to-mm。长期更可靠的是校准相机到末端、真实接触点及面板法向，在面板坐标中规划。

可考虑新增准备技能、受限接近/后撤工具，但名称和参数属于拟议设计，目前不可调用。更改动作集合时应版本化：当前v2 press仍保持立即回程语义，新工具不可暗中改变其含义。

**分步实验，而不是一次放开全部控制**

1. 离线理解实验：只读取本次示范，输出目标、阶段和证据；分别测试腕图、双图、双图+动作参考。先验证endpoint多图和工具调用兼容性，记录真实模型ID、模型配置、图片分辨率、输入规模与延迟。`qwen38`是代码中的服务名，不足以确认具体权重。
2. 离线决策实验：取若干before快照作为“当前观测”，比较无示范、文字流程、双视角+动作参考；评分动作可执行性、方向、阶段、是否识别缺图/遮挡、是否虚报成功。示范与测试同源时只能验证理解/格式，不能报告泛化；需要另录轨迹或不同起点做留出测试。历史回放无法验证模型新动作的真实后果。
3. 最小实机闭环：人工摆到接近示范第6步的准备位，先验证对齐、单次按压和验证撤回。此时可以尽量复用旧move/press，但只能称“简化末段任务”，不称完整复现第7–10步。
4. 完整流程：补头部/准备姿态、持久接近、后撤能力，显式处理新的参考平面。先在无接触阶段检查命令和实测位移及符号，再接入按压。对SDK路径差异单独验收。
5. 稳健性实验：从小范围变化的起点、距离、视角和光照开始；比较有/无示范，按首次成功、允许重试后成功、人工接管数、耗时/轮数、误报成功分别统计。试验前确认按钮状态已复位，避免把上轮的亮灯算成本轮成功。

优先补录按压前后短时序双视角图像、同步实测位姿/关节/力矩（若可用）、独立按钮事件、操作者成功标签及对应时间。需要记录真正接触点与测距点的关系。结果验证优先用电梯/按钮侧信号；无信号时用时间一致且处理遮挡/反光的视觉检测，保留unknown状态和必要的人工作证。

首个工程增量建议是“示范加载器 + 双视角请求构造 + 离线回放评估”。它能回答Qwen是否从这条示范得到有效帮助，随后才有依据扩展动作接口。多次成功/失败轨迹积累后，再考虑训练VLA或引入ENPIRE式自动改进；一条边界截图序列目前更适合agent参考资料。
