# S1B 右手平面控制与相机测距

本文对应 2026-11-01 的当前实现。分支：`feat/right-arm-planar-control`。

当前提供以下入口，无需训练新模型：

| 入口 | 用途 | 启动脚本 | 默认端口 |
|---|---|---|---|
| Agent 一键启动与网页 | 默认加入成功示范和失败复盘，同时查看双相机和 Agent 逐轮输出 | `scripts/s1b_agent_run.py` | 网页 8766 |
| 直接 SDK 键盘控制 | 人工移动右臂、前伸、开合夹爪，可选相机网页 | `scripts/s1b_keyboard_direct.py` | 网页 8765 |
| Thor 示范自动闭环 | 示范和实时双视角请求 Qwen，共用键盘执行器自动执行 | `scripts/s1b_agent_service.py` + `scripts/s1b_agent.py` | API 6210 / 模型隧道 18000 |
| 标定控制服务 | Agent 调用观察、平面微移、按压、状态和停止 | `scripts/s1b_planar_control.py` | API 6210 |

键盘入口不加载离线标定配置。标定控制服务需要完成现场标定，仓库示例配置不能直接执行运动。相机网页只管理画面和测距点，不提供机械臂运动接口。

## 工具尺寸

右手夹爪末端长度为 **150 mm（0.150 m）**，由用户于 2026-10-30 提供。此处记录机械尺寸；长度的测量基准与坐标轴方向尚未指定，当前未据此修改 TCP 变换或运动配置。

## 快速启动

在工作站仓库目录的交互终端运行：

```bash
python scripts/s1b_keyboard_direct.py --host S1B --view-cameras --speed-mm-s 20
```

等待终端显示网页已就绪，然后打开 <http://127.0.0.1:8765>。机器人 XYZ 位移在终端输入，测距点方向键在网页输入。

启动器自动将脚本、网页服务和深度参数助手复制到机器人临时目录，加载已有 SDK / ROS 环境，通过 SSH TTY 运行并建立本地端口转发。退出后清理临时目录和网页进程；已保存的测距点不受影响。不开 `--view-cameras` 时不启动网页。

SDK 提示已有控制者时，输入完整的 `yes` 再回车才会接管；接管会停止原控制器的运动。回车、`no` 或输入结束表示不接管。无效输入会重新询问。控制模式启动前会清理积压的终端按键。

### 命令行参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--host` | 不指定 | SSH 主机，如 `S1B`；省略则在当前机器直接使用 SDK |
| `--sdk-root` | `/home/astribot/astribot_sdk_aarch64` | SDK 目录 |
| `--step-mm` | `2` | 兼容旧命令，XYZ 输入方式不使用此参数 |
| `--speed-mm-s` | `20` | 笛卡尔目标轨迹峰值速度，mm/s |
| `--control-hz` | `250` | SDK 与发送循环的共同频率，Hz |
| `--view-cameras` | 关闭 | 开启独立相机网页进程 |
| `--view-port` | `8765` | 网页和 SSH 转发端口；占用时可改为 8766 |

提高移动速度使用 `--speed-mm-s`，每轮位移直接输入 XYZ 毫米数，不设软件位移上限。`--control-hz` 不代表移动速度。轨迹使用五次平滑插值，每段最短 0.2 秒；100 mm 前伸在默认 20 mm/s 下目标轨迹约 9.4 秒，SDK filter 可能增加实际到位时间。

### 终端 XYZ 输入

方向按机器人底盘坐标定义：+X 向前、+Y 向左、+Z 向上，和画面方向不一定相同。每轮依次输入三个毫米数：

```text
X 位移（mm，正数向前）：
20
Y 位移（mm，正数向左）：
-5
Z 位移（mm，正数向上）：
10
```

Z 回车后一次执行三轴合成移动，输入 X/Y 时不会开始移动。支持正数、负数、小数、零，不设软件位移上限。位移从上一命令目标累加，启动时以实测位姿初始化；朝向和躯干目标保持不变。XYZ 全为零时不移动，直接开始下一轮。

- 任一步直接回车取消本轮并回到 X；非法数字重新输入当前轴。支持正常终端退格编辑。
- 任一步输入 `q` 并回车，或随时 Ctrl-C，停止退出。
- 在 X 提示处输入 `h` 并回车，依次输入头部左右转角 yaw、俯仰角 pitch，单位为度、目标为绝对角度。两项齐全后调整头部，完成后返回 X；空输入取消，q 或 Ctrl-C 停止。默认头部插值峰值速度 20 度/秒，可用 `--head-speed-deg-s` 调整。头部自动跟随保持关闭。
- 在 X 提示处输入 `c` / `o` 并回车，闭合 / 打开右夹爪。默认保持原夹爪开度。
- 执行期间丢弃额外输入，不排队运动；`q` 回车和 Ctrl-C 仍可停止。结束后再提示下一轮。

沿用原 Cartesian 发送循环和五次插值。完成提示只表示插值指令已发送完毕，不代表实测到位；不增加跟踪误差、漂移或到位门槛。SDK 和驱动自身行为不变。原 WASD/F/R 按键流程已替换。键盘与 Agent 均调用 `s1b_keyboard_control.CommandExecutor`，支持 XYZ、头部角度和 c/o；Agent 不再使用独立平面/按压执行逻辑。

已知 SDK 发送频率警告只显示首次，退出时统计折叠数量；其他错误保留。网页深度不会自动限制输入行程，XYZ 输入是位置控制，不是自动按钮按压。

## 可选操作记录模式

```bash
python scripts/s1b_keyboard_direct.py --host S1B --record
# 指定新的本地目录（不能已存在）：
python scripts/s1b_keyboard_direct.py --host S1B --record-dir outputs/keyboard_run_001
```

`--record` 自动开启相机网页，默认本地目录为 `outputs/keyboard_sessions/<北京时间_会话ID>/`。`--record-dir` 隐含开启记录；不启用时保持原控制流程。

记录 XYZ、头部角度、夹爪、零位移、输入行、无效输入、取消、忽略输入、停止和异常。每次已提交操作有独立编号，保存起点/目标命令位姿、毫米位移或夹爪目标、速度、开始/结束时间和状态。开始画面在目标更新前抓取；完成画面在最终目标成功发送后抓取。头部记录包含起始角度、目标角度和角速度（度/秒），也保存开始及完成画面。夹爪完成仅表示目标首次成功发送，XYZ 和头部完成仅表示插值发送完成，均不声明实测到位。

每次开始/完成保存头部 JPEG、右腕 JPEG、原始深度 `right_depth_raw.npy`、帧时间戳、相机参数、测距点及测距值。会话另有初始、最终画面。不录连续视频，不补录开启前的操作。

```text
session.json             # 会话设置、退出原因、记录完整性及错误
events.jsonl            # 逐行事件（包括输入和忽略情况）
summary.md               # 操作列表及前后图片预览
initial/                 # 初始画面
operations/000001/
  operation.json         # prepared / running / completed / interrupted
  before/                # 开始画面及 capture.json、metadata.json
  after/                 # 完成或中断后的画面
final/                   # 停止后的最终画面
```

抓图最多等待 2 秒的新帧；缺图或磁盘写入失败明确提示并标记不完整，不阻断原控制，不重试动作。记录工作不在控制循环或发送锁中执行。取消和无效输入只记事件，不额外抓图；未提交的半行输入在清空终端时只标记为丢弃，不宣称保留每次按键。

SSH 模式先落盘到机器人 `~/.local/share/pressb/keyboard_sessions/<会话ID>/`，退出后自动复制到工作站。复制失败会显示原件路径，可手工 `scp -r S1B:<显示的远端目录> <本地新目录>`。临时部署目录清理不会删除记录。硬杀进程留下的 prepared/running 操作表示未确认完成，不自动推断成功。Ctrl-C 优先停止机器人，再尽力保存最终画面；启动或 SDK 失败同样记录退出原因。

## 双相机网页与测距点

网页显示头部和右腕彩色画面。右腕绿色十字是当前测距点，方框是以它为中心的 5×5 像素区域。

1. 点击右腕画面中的目标位置，或先点击网页空白处使网页获得焦点。
2. 在网页按 ↑ / ↓ / ← / →，每次移动 1 个原始图像像素；Shift + 方向键每次移动 10 像素。支持长按，点位不会越过边界。
3. 点击“保存测距点”，看到已保存提示后，下次启动会恢复该位置。
4. “恢复画面中心”只改变当前选择；再次保存才会覆盖已保存设置。

选点只改变图像中的测量位置，不驱动机器人，也不跟踪物体。关闭浏览器再打开仍使用当前服务端选择；重启服务读取磁盘中最后保存的位置。连续选点会串行提交最新选择，旧点的计算结果不会覆盖新点。

配置保存在**机器人运行用户的 home 目录**：

```text
~/.config/pressb/right_wrist_depth_point.json
```

在当前 S1B 用户环境通常为 `/home/astribot/.config/pressb/right_wrist_depth_point.json`。保存采用原子替换；失败会在网页显示错误。文件格式见[接口参考](interfaces.md#测距点配置文件)。

### 距离读数含义

- 主读数：深度对齐到右腕彩色图后，选定点周围 5×5 区域有效深度的中值，显示单位 mm。
- 辅助读数：选定单像素深度、区域有效像素数和 RGB / 深度时间差。边缘区域裁剪到图像边界。
- 深度是相机光轴 Z 距离，不是夹爪接触点到面板的间隙，也不是空间欧氏距离。
- 无有效值显示“—”。RGB / 深度配对允许最大 80 ms 时间差，超过 1 秒的数据标为过期，不沿用上次距离冒充当前值。
- 网页约 5 Hz 更新；深度暂停时仍可刷新 RGB。相机订阅和计算运行在独立进程，不在终端逐帧输出。

系统读取右腕设备的真实深度尺度、出厂内参和深度到彩色外参，进行重投影和最近表面选择。2026-10-30 核查的右腕原始深度为 640×360 uint16，尺度约 0.0001 m/count。**0.1 mm 是量化单位，不是测量精度承诺**；当前未完成不同距离、材质和角度下的误差标定。

网页进程复用现有 ROS 相机流；完全收不到消息时会尝试启用已有相机服务。退出不会关闭共享相机驱动。需要机器人已安装的 cv2、NumPy、ROS、g++ 和 librealsense2。

### 单独运行相机网页

在已加载相机 ROS 环境的机器人端，将网页脚本和 C++ 助手放在同一目录后运行：

```bash
python scripts/s1b_camera_view.py --port 8765 \
  --point-config ~/.config/pressb/right_wrist_depth_point.json
```

此入口不创建机器人控制客户端。在工作站另开隧道：

```bash
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 S1B
```

`--point-config` 是独立网页脚本的参数，直接键盘启动器目前不透传该参数。

## 常见问题

| 现象 | 处理 |
|---|---|
| 页面没有“测距点微调”提示，方向键无反应 | 退出并重新运行带 `--view-cameras` 的命令，再刷新页面；仅刷新不会更新旧进程中的网页代码 |
| 方向键滚动其他页面或没有反应 | 先点击相机网页空白处，使浏览器页面获得焦点；不要在终端输入方向键 |
| 点击无反应 | 使用网页方向键；检查页面是否加载到右腕画面，以及是否显示选点请求错误 |
| 配置未保留 | 确认点击了保存并成功；文件在机器人上，且需用同一个机器人用户启动 |
| 页面连接拒绝 | 等待“网页已就绪”；检查一次性启动错误或端口占用，可更换 `--view-port` |
| 未取得控制权 | 重新运行，在 SDK 提示中准确输入 `yes`，或先退出原控制程序 |
| 有画面但无距离 | 查看深度状态、有效像素数和时间差；换一个有有效深度的测距点 |

开启网页时，启动器在申请 SDK 控制权前等待网页健康检查通过；启动失败会报告并退出。运行中网页子进程退出会提示一次，键盘控制继续。关闭键盘程序后，网页连接中断是预期行为。
