# Qwen 示范与双视角自动闭环

当前键盘和 Agent 共用 `scripts/s1b_keyboard_control.py` 中的 `CommandExecutor`。键盘解析终端输入，HTTP 服务转交模型命令；SDK 目标生成、插值、发送和完成判定只有一份实现。

## 启动

推荐使用一键入口，在仓库目录运行：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_run.py
```

默认使用最新成功键盘示范 `20261101_182424_352b5047` 和现场失败案例 `20261101_184824_dcb23038`，目标为“按下电梯外呼向下按钮并撤回”。新示范第10步双视角确认按钮亮起；第11步后撤中断、after和final缺失，保留原记录，不能解释为撤回完成。启动前检查失败案例及关键图片，缺失时报错；随后启动 S1B 服务，终端出现 SDK 提示时输入 `yes`；服务就绪后自动启动 Qwen Agent，并由 Agent 自己管理 Thor 隧道。

后续测距点沿用本次右腕像素 `(433,287)`（640×360），归一化坐标 `[0.6776212832550861,0.7994428969359332]`，已核对保存在机器人 `/home/astribot/.config/pressb/right_wrist_depth_point.json`。键盘和Agent相机服务都从此配置加载；示范目录保留 `measurement_point.json` 副本及 `point_persistence.json` 核对记录。

打开 <http://127.0.0.1:8766>，可同时查看头部/右腕实时画面、每轮动作参数、模型理由、执行状态、原始模型输出和运行日志。网页“停止执行”、终端 `q` 回车或 Ctrl-C 均可停止。任务结束或网页停止后，网页保留最后保存的观测并明确标记为非实时，Ctrl-C 关闭网页。默认仅监听本机，不向外网发布。

每次自动创建 `outputs/agent_web/<时间_ID>/`：`agent/` 保存完整 Agent 数据，`terminal.log` 保存终端输出，`launcher.json` 保存启动状态。可用 `--goal`、`--demo`、`--output`、`--max-rounds` 修改任务配置；`--web-port` 默认8766。启动前请退出占用6210、8765、8766、18000的旧服务。

`--failure-case <运行目录>` 选择包含 `case_review.json` 和 `agent/` 的已复盘失败案例；也支持含 `case_review.json` 和 `rounds/` 的直接 Agent 输出目录。`--no-failure-case` 显式关闭失败上下文。单独调用 `s1b_agent.py` 时默认不加载失败案例，需要像下面一样传参；现有 `--demo` 用法兼容。

需要分别管理进程时，也可使用下面的双终端方式。

终端一（工作站仓库目录）：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_service.py --host S1B
```

沿用 SDK 控制权提示。服务启动时保持夹爪开度，不自动闭爪。看到“Agent API 已就绪”后，终端二运行：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent.py \
  --goal '按下电梯外呼向下按钮并撤回' \
  --demo outputs/keyboard_sessions/20261101_182424_352b5047 \
  --failure-case outputs/agent_web/20261101_184824_dcb23038 \
  --output outputs/agent_keyboard_001
```

输出目录必须是新目录。默认自动建立 Thor 隧道；已有模型隧道可用 `--model-base http://127.0.0.1:18000/v1`。相机网页为 <http://127.0.0.1:8765>。

Agent 每轮自动执行一个命令并获取新画面，不询问 y。两个终端均支持 `q` 回车或 Ctrl-C 停止；客户端等待模型时仍可停止，迟到响应不会执行。默认最多20轮，可用 `--max-rounds` 改变。模型错误、无法继续或报告完成后结束并停止服务。现场结论需与模型结论区分，不自动把模型报告写成人工确认成功。

提示词要求：只有在本轮实时画面中看到目标按钮指示灯亮起，才能判定触发；报告整个任务完成还需撤回证据。允许保持夹爪张开、用单边手指按压，也允许尚未确认触发且深度无效时依据实时画面继续前推。无效深度本身不禁止移动，也不能被当成成功证据。

提示词加入最新成功示范第10步亮灯后的约131 mm测距参考（原记录131.29 mm，右腕像素433,287，20/25有效像素）。点位、手部构型和对齐情况相似时，用它辅助判断接近尺度与精细调整；不将其当作夹爪长度、固定目标、行程限制或触发阈值，也不使用“当前深度减该数值”生成位移。当前图像与反馈优先，点位或场景改变时重新判断。提示词在Agent启动时加载，修改后对新启动的会话生效。

## 与键盘一致的动作

| 命令 | 字段 | 行为 |
|---|---|---|
| move | `xyz_mm: [x,y,z]` | 底盘坐标毫米增量；+X前、+Y左、+Z上；从上一命令目标累加，朝向不变 |
| head | `head_deg: [yaw,pitch]` | 头部绝对角度，单位度，对应 h |
| gripper | `key: "c"` 或 `"o"` | 闭合/打开，对应同名键 |
| stop | 独立停止接口 | 停止会话，不自动撤回 |

默认平移20 mm/s、头部20°/s、控制250 Hz；服务端用 `--speed-mm-s`、`--head-speed-deg-s`、`--control-hz` 修改。只验证有限数及命令结构，与键盘相同，不增加独立行程上限、跟踪误差门槛或到位等待。

启动和未操作夹爪时走 Cartesian 接口；c/o 后使用键盘已有 mixed 接口，头部调整走头部关节接口。只有一个 SDK 写线程。完成表示最终指令发送完成；夹爪为首次成功发送，不表示实测到位或按钮触发。

旧 Agent 的 right/up、固定X平面、press自动往返、depth−150强制距离及20/100mm限值已移除。前伸、按压和撤回均由模型显式生成XYZ增量，深度仅为参考。

## 上下文与日志

`--demo` 直接读取原始键盘 `session.json` 和 `operations/*/operation.json`。每步一张前后双视角拼图，上方before、下方after，左head、右wrist；附带原始命令、深度和缺失信息。成功来源单独记录为用户确认，原始final缺失保持原样。

默认每轮发送最新成功示范11张操作图、失败案例第8/11/14轮前后双视角3图、当前头部/腕部原图2张，共16张；同时提供当前实测状态和最近5轮文字反馈。成功示范第11张明确标注中断，缺失的after显示MISSING，不补造撤回证据。最新失败案例保留全部14条实际动作、原模型理由、执行结果、前后深度与关键实测/命令位姿；第15轮保留为模型请求中断，无执行动作。历史失败图有独立标签，不能作为当前状态或成功配方。关闭失败上下文时，11步示范和当前双视角为13图。图片总数随所选示范步数计算，模型服务必须接受实际图片数量，不丢图或自动降级。

最新失败案例的 `case_review.json` 和 `case_review.md` 记录现场反馈“没有对准、压在边缘”，以及头部图可见偏置、腕图遮挡、未执行横向精调和连续前推等证据。第7–14轮只改X、累计前推85 mm；最后3轮再前推15 mm，测距仅从约131.54变到130.99 mm，没有确认亮灯。模型多次写“之后重新检查对齐”，却未实际调整Y/Z。成功示范的横向-20 mm仅作比较，不变成固定补偿。分析区分用户反馈、图像/日志事实和推断，原始日志保持不变。旧失败案例 `20261101_174626_c319289f` 仍保留，需要时可通过 `--failure-case` 显式选择；当前默认只加载最新失败案例，图片总数保持16张。

提示词要求接近/按压时用现有reason说明目标可见视角、实际接触手指、残余偏差和本次调整依据；目标丢失或重复前推没有新触发证据时重新评估。允许单边按压、无效深度下继续前推的规则不变，不新增执行器限制，也不强制下降50 mm。

历史验证：2026-11-01 使用旧成功示范 `20261101_165200_b34ebc84` 和保存的末态观测验证了15图请求，`qwen38` 在约35.9秒返回合法工具调用，报告89498个输入token。目录 `outputs/agent_context_validation_20261101_failure_v1_retry/` 保留完整请求、响应和结果（`replay_only`、执行命令数0）；这不是当前16图配置的模型验证。首次验证中断记录另保留在不带 `_retry` 的目录。

历史图和当前图有明确标签，命令位姿不冒充实测。原始final缺失保持缺失，不丢弃完整操作边界。图片预编码后在进程内复用。图像及模型请求较大，预留日志磁盘空间。

本地保存：

- `demonstration/reference.json` 与步骤拼图；`task.json`、`session.json`。
- `failure_case/reference.json`、`case_review.json` 与3张失败拼图：保存分析版本、完整动作文字和来源文件SHA-256；`task.json` 保存案例来源及每次请求预期图片数，实际请求完整保存在 `rounds/*/request.json`。
- `observations/`：头部/腕部原图、原始深度、实测状态和manifest；下载验证SHA-256。
- `rounds/`：请求、原始响应、解析动作、对应观测ID与执行结果。
- `commands/`、`tasks/`：带唯一ID的实际请求与结果；服务端另保留state_trace。
- `result.json`：停止原因、已完成动作数和模型结论；`human_verified_success`、`human_verified_retracted`默认为null，由现场记录补充。

模型一次只返回一个合法工具调用，非法格式最多修正一次；模型网络错误不产生替代动作。已执行动作采图/保存失败时不重放。深度值缺失是unknown，缺失新鲜相机帧则本次观测失败。

## HTTP 接口与兼容性

保留端口6210及 `/v2` 路由，session schema改为 `pressb-agent-keyboard-v1`。新版客户端拒绝旧session；新版服务拒绝旧平面/press参数。旧日志仍可查看，不自动重放。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/v2/session` | 命令契约、速度、坐标和会话ID |
| POST | `/v2/observations` | `{session_id,command_id}`；异步采集任务 |
| POST | `/v2/actions` | `{session_id,command_id,observation_id,type,...命令字段}` |
| GET | `/v2/tasks/{task_id}` | 执行、采集、保存结果 |
| GET | `/v2/state` | 当前状态、故障和实测状态 |
| GET | `/v2/observations/{observation_id}` | 不可变观测清单 |
| GET | `/v2/artifacts/{artifact_id}` | 清单登记的文件 |
| POST | `/v2/stop` | `{}`；停止并关闭会话 |

一个动作在途时拒绝新动作；相同command_id与相同参数返回原任务，不重复运动。动作必须引用最新观测。HTTP202是接受任务，不表示完成。服务重启标记旧未完成日志为interrupted，不继续执行。已有 `--replay` 可用于Agent观测目录，只调用模型、不连接机器人；它不是现场实验的前置要求。
