# Qwen 示范与双视角自动闭环

当前键盘和 Agent 共用 `scripts/s1b_keyboard_control.py` 中的 `CommandExecutor`。键盘解析终端输入，HTTP 服务转交模型命令；SDK 目标生成、插值、发送和完成判定只有一份实现。

## 启动

推荐使用一键入口，在仓库目录运行：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_run.py
```

默认使用 `--decision-mode localized`：**当前双图独立定位 → 原始坐标偏差与实际执行反馈 → 模型按明确方向规则选择调整量 → 正X候选检查腕图二维重叠 → 原共享执行器**。关闭 thinking、不放失败案例，默认加入成功键盘示范 `20261101_182424_352b5047` 的完整全过程：第1–11步全部动作、状态、深度说明及11张步骤拼图。目标为“按下电梯外呼向下按钮并撤回”。第11步后撤中断、after和final缺失，完整归档和限制说明保留，不能解释为撤回完成。启动前检查示范记录及必需图片，缺失时报错；显式截取末段时另核对人工确认的亮灯边界；随后启动 S1B 服务，默认在 SDK 初始化的控制权接管提示中自动回复 `yes`，无需手动输入；服务就绪后自动启动 Qwen Agent，并由 Agent 自己管理 Thor 隧道。

默认提示词为 `agent_system_prompt_localized.txt`，使用白色／米白色箭头所指的物理指端作为接触参照。程序先统一定位坐标单位；连续动作没有明确改善或连续正X前推达到3次时，先进行独立假设复核，再请求新的动作决策。全部动作工具仍提供，程序不把图像偏差换算成XYZ。先用Y/Z对齐，偏差明显且方向有依据时采用较大调整，接近后再减小步幅，也可同时调整Y/Z；不设固定步幅。每个正X候选必须另用当前腕图检查：箭头所指物理指端落入按钮可按区域框内，横向和纵向均满足才放行。未知或不满足时拒绝整条候选，继续由模型选择Y/Z、改善取景或后撤。原“腕图横向位于两指之间”条件不用于默认流程。触发复核时须填写 `reassessment`，不用旧的 `visual_basis`。约30°低头只是取景参考，XYZ仍由模型选择。

正常每轮一次独立定位调用加一次动作调用，异常触发轮额外一次只读复核。定位只接收当前两张原图、目标与参照说明，不带案例、历史动作理由或待执行动作。定位输出保留单位、双视角可见性、按钮/标记框和物理指端；`note` 默认省略，仅在结构字段不足以表达重要不确定性时使用至多3个英文词或8个汉字（如“指端遮挡”），不复述背景和物体外观，也不输出工具调用之外的正文。旧记录的长说明仍正常读取；不因说明略长而重试或截断，`max_tokens=512` 保持不变。复核独立使用前后双视角4张原图、规范化偏差和实际命令。动作请求继续保留案例和持续历史，默认第一轮11张案例图＋2张当前图，共13张；未压缩时第N轮为 `11+2N` 张。完整案例作为会话固定前缀保留，压缩早期运行过程时也不截掉案例步骤。动作结构解析和上下文压缩仍按需处理。压缩摘要只消费一次回答，容忍附带正文、空字段或额外字段，不检查模型声称的事件顺序；原始摘要作为模型判断保留，只有属于本次运行的观测引用才加载对应图片，程序动作统计不因压缩清零。`--decision-mode direct|separated|grounded` 保留旧版行为供显式对照，旧模式中的阈值与门控不属于当前默认流程；显式 `--prompt` 优先于按模式选择的默认提示词。

当前 localized 对齐方向在提示中明确指定，模型选择毫米幅度：以**腕图中的箭头所指物理指端**为参照，按钮可按面完全偏左→`+Y`，偏右→`-Y`，偏上→`+Z`，偏下→`-Z`；对应按钮投影向右、左、下、上靠近指端。某轴上指端已位于按钮面范围内，该轴置零，不要求精确对准中心。例如左上方使用 `[0,+a,+b]`，a/b由模型根据尺度和反馈选择，先大后小。此表来自本装置纯Y/Z动作前后图，只适用于当前腕部安装、未镜像原图及保持的手部朝向，不能直接用于头图或其他相机姿态，也不是像素到毫米标定。

程序还把方向表应用到当前规范化腕图定位，在每轮动作请求末尾加入 `CURRENT_WRIST_ALIGNMENT_DIRECTION_RULE`，直接给出 Y/Z 的 `+1/-1/0/null`，绑定本轮观测ID。`0`表示该轴位于按钮框范围内，`null`表示未知；局部可见只能产生带不确定性说明的方向提示，不能授权前推。记录在 `rounds/<轮次>/wrist_direction_rule.json`，不改写先前消息；此计算不调用额外模型、不生成毫米位移。

同方向已改善且尚未越过目标时，继续该方向；禁止仅因为“恢复了视野”就又反向。框尺寸和指端身份变化可能使 `error_button_units` 虚假变小，需核对同一对象在原图和像素偏差中的变化。取景或实际运动与方向表冲突时，先重新识别、复核映射。这些是模型提示要求，**不是新增的Y/Z方向硬校验**；模型仍输出原 `xyz_mm`，执行器不自动改写或裁剪。正X仍必须通过当前腕图重叠检查，放行后不增加步长上限。保存画面的方向核实与回放见 [方向规则记录](../../report/20261102_wrist_direction_rules/README.md)。新提示在下一次启动生效，不热更新正在运行的会话。

后续测距点沿用本次右腕像素 `(433,287)`（640×360），归一化坐标 `[0.6776212832550861,0.7994428969359332]`，已核对保存在机器人 `/home/astribot/.config/pressb/right_wrist_depth_point.json`。键盘和Agent相机服务都从此配置加载；示范目录保留 `measurement_point.json` 副本及 `point_persistence.json` 核对记录。

需要复现之前白色箭头的 **旧 direct 对照流程** 时使用以下命令。提示词文件名保留 `red_marker`，兼容原启动命令，内容已改为白色箭头；这条显式指定 direct 的命令不会进入新 localized 流程：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_run.py \
  --decision-mode direct --demo-last-steps 3 --no-failure-case \
  --prompt docs/astribot/planar_control/agent_system_prompt_red_marker.txt
```

这条命令让 Qwen 直接根据成功示范、当前双视角、实测状态和对话历史选择动作，关闭 thinking；首次动作请求共5张图，随后按持续会话追加。白色箭头指定的是它所指的**物理手指前端**，不是整块贴纸的中心；箭头图案的方向不代表机器人运动方向，也不构成接触点标定。跨视角身份看不清时保留未知。仍使用 direct 动作决策，不引入 grounded 的阶段或步长建议。

direct 的进展监测模式现在先进入 `get_view`。独立只读检查只接收当前双图，定位按钮框、箭头框及箭头指向的物理指端；程序从定位计算图像平面上下／左右关系，仅用于检查视觉描述和取景，不生成XYZ或毫米补偿。头图尚不能辨认面板、按钮及接触指端时，只提供调整头部、重新观察、报告无法继续三个工具，动作模型不能跳过取景先移动手部或夹爪。模型自行选择头部角度，约 `head [0,30]` 是绝对角度参考，不是固定启动动作；已有足够视野时可直接通过检查。头部发送完成仍不等于取景成功，下一观测需要重新检查。这个阶段在首次取景、头部改变以及冲突恢复时增加独立调用，thinking保持关闭。grounded和separated的原流程不受此改动影响。

direct 现启用“进展监测＋异常时复核”。正常轮次仍只有一次动作模型调用，模型随动作提供当前观测 ID、子目标、所用视角、按钮相对指定指端的上下／横向关系，以及上一步效果。程序另外记录真实完成命令的连续方向和累计位移，区分模型判断与执行事实。同方向连续平移3次，或出现无改善、恶化、跨过目标或缺少进展依据等异常时，额外发起一次只读复核：仅输入相关 BEFORE/CURRENT 头部和腕部原图共4张，以及期间实际执行的命令和发送结果，不带历史理由、案例或待执行动作。复核不输出坐标补偿或机器人动作。

复核结果绑定观测 ID 并送回动作决策。对上一动作同轴同方向的继续提议，复核须支持仍在改善；到达图像目标、跨过、无改善或未知时要求重新决策。动作模型与复核对当前上下／左右关系有冲突时，程序进入 `recover_view`，将双方观点记录为模型判断分歧，不再强迫动作模型把自己的答案改成复核答案。这个阶段只允许头部调整、重新观察或报告无法继续；获取新观测并完成取景检查后再判断。程序不裁剪或改写位移，也不自动反向。候选不满足条件时持续要求模型修正，不设修正次数上限；复核的格式或证据引用非法时也继续修正。网络请求失败、人工停止仍结束本次运行，不绕过复核。正常的连续有效调整可以继续，重复次数本身不是失败判定。每轮 `progress.json` 和 `progress_review/` 保存判断、触发原因、请求响应和耗时；网页分别显示进展与复核，并明确它们不是人工确认。该机制仍依赖视觉判断质量，不能保证消除错误循环。

每轮 `view_state.json` 保存取景阶段、对应观测及恢复原因，`view_acquisition/` 保存独立定位请求、原始响应、修正、判读和token／耗时；`progress_review/conflict.json` 保存冲突双方的判断。网页区分“取景检查”“取景决策”“冲突恢复”，显示定位所用观测ID，避免把当前视频与旧判读混为一谈。历史记录没有这些字段时仍正常显示。按钮通常高于初始手指的现场经验只用于首次高度决策的低置信度先验；实时图像和动作效果优先，开始移动、达到同高或跨过目标后不得继续沿用该先验。

之前用户指定的正X腕图横向前推检查继续保留，候选前推时额外调用。它仍只检查按钮横向位于两指之间，不添加高度、深度或闭爪条件；进展复核单独检查重复动作是否还有依据。共享执行器、HTTP 动作参数、发送完成语义、亮灯和撤回证据要求均保持原有语义。`--prompt` 的实际绝对路径记录在 `launcher.json`，内容记录在 `agent/task.json` 和模型请求中；缺失文件在 SDK 接管前报错。新启动加载本次修改，历史运行保存的提示词和原始记录不改写。本次实现后由现场人员启动真机，代码检查与保存图像回放不作为任务成功证明。

一键入口默认启用 `--auto-confirm`，上面的 direct 命令可直接使用，无需追加参数。需要手动确认时追加 `--no-auto-confirm`。自动确认只作用于 SDK 初始化，实际模式记录在 `launcher.json` 的 `auto_confirm` 字段；仍需在交互终端运行，以保留 `q` 回车停止功能。

打开 <http://127.0.0.1:8766>，可同时查看头部/右腕实时画面、每轮动作参数、简短模型理由、执行状态、输入/输出token、图片数、压缩状态、原始模型输出和运行日志。网页“停止执行”、终端 `q` 回车或 Ctrl-C 均可停止。任务结束或网页停止后，网页保留最后保存的观测并明确标记为非实时，Ctrl-C 关闭网页。默认仅监听本机，不向外网发布。

左侧顶部的“Agent 识别快照”默认跟随最新轮次，可切换头部/右腕、选择历史轮次或隐藏识别标记：黄框是按钮、紫框是箭头标记、青色十字是物理指端，连线由定位坐标计算。标记只叠加到该轮观测ID对应的保存原图，不覆盖下方实时视频。最新轮尚未返回定位、格式无效、观测ID不匹配或图片缺失时会明确显示状态，不沿用上轮识别框。框是模型估计，可能不准确。

正在运行的网页不会热加载新版代码。可用同一网页模块只读查看已有运行，无需重启机器人或Agent：

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_dashboard.py \
  --run-dir outputs/agent_web/<运行目录> --port 8767 \
  --camera-base http://127.0.0.1:8765
```

打开 <http://127.0.0.1:8767>。该独立入口禁用停止操作，只读取运行记录和已有相机服务；省略 `--camera-base` 时显示最后保存的画面。停止机器人仍使用原控制页面或原启动终端。下次一键启动的8766页面会直接包含识别快照区域。

每次自动创建 `outputs/agent_web/<时间_ID>/`：`agent/` 保存完整 Agent 数据，`terminal.log` 保存终端输出，`launcher.json` 保存启动状态和实际示范选择。可用 `--goal`、`--demo`、`--demo-last-steps`、`--output`、`--max-rounds`、`--context-budget-tokens` 修改任务配置；`--web-port` 默认8766。启动前请退出占用6210、8765、8766、18000的旧服务。

`--demo-last-steps N` 选择截至人工复盘确认亮灯边界的最后N个完整动作，N必须为正整数，不能把中断后撤算入成功动作。所有模式不指定该参数时均保留完整示范；显式指定时仍按N截取。`--failure-case <运行目录>` 可显式加入包含 `case_review.json` 和 `agent/` 的已复盘失败案例，也支持含 `case_review.json` 和 `rounds/` 的直接 Agent 输出目录。`--no-failure-case` 显式关闭失败上下文。localized/grounded默认无失败案例；一键入口的direct/separated模式保留此前失败案例 `20261101_184824_dcb23038` 默认值，单独调用 `s1b_agent.py` 则仍默认不加载失败案例。现有 `--demo` 用法兼容。

```bash
  --decision-mode localized --no-failure-case \
  --output outputs/agent_keyboard_001
```

输出目录必须是新目录。默认自动建立 Thor 隧道；已有模型隧道可用 `--model-base http://127.0.0.1:18000/v1`。相机网页为 <http://127.0.0.1:8765>。

Agent 每轮自动执行一个命令并获取新画面，不询问 y。两个终端均支持 `q` 回车或 Ctrl-C 停止；客户端等待模型时仍可停止，迟到响应不会执行。默认最多20个外层决策轮次，可用 `--max-rounds` 改变。默认localized校验命令结构、当前腕图正X放行结果，以及触发复核后 `reassessment` 的必需字段和观测绑定；它不自动验证自然语言理由是否与XYZ方向一致，也不能保证视觉结论正确。格式修正不消耗外层轮数，不设内部次数上限。网络请求失败、人工停止、模型报告无法继续或报告完成后结束并停止服务。现场结论需与模型结论区分，不自动把模型报告写成人工确认成功。

提示词要求：只有在本轮实时画面中看到目标按钮指示灯亮起，才能判定触发；报告整个任务完成还需撤回证据。允许保持夹爪张开、用单边手指按压。默认localized通过当前腕图重叠检查后，即使尚未确认触发或深度无效，也可依据画面继续前推。无效深度本身不禁止移动，也不能被当成成功证据。

案例摘要提供最新成功示范第10步亮灯后的约131 mm测距参考（原记录131.29 mm，右腕像素433,287，20/25有效像素）。点位、手部构型和对齐情况相似时，用它辅助判断接近尺度与精细调整；不将其当作夹爪长度、固定目标、行程限制或触发阈值，也不使用“当前深度减该数值”生成位移。当前图像与反馈优先，点位或场景改变时重新判断。提示词在Agent启动时加载，修改后对新启动的会话生效。

当前 localized 提示词明确四类视觉子目标：取景时看清按钮可按区域和箭头所指物理指端；有明显横向/高度偏差时优先改善对齐；接近/按压时说明当前依据并检查预期变化；看到本次亮灯后撤回并核对证据。对齐参照是选定接触指端，不是画面中心；部分按钮框不当成完整中心，投影重叠不当成三维接触。每轮在原有简短 `reason` 中说明当前子目标和预期画面变化，不新增动作字段；其中正X发送前另有下述腕图二维重叠检查。约30°低头仍只是取景参考，不要求已经有用的画面再次低头；无效深度、未触发和单边按压的原有许可保留。本次更新在下次启动时生效，不自动重启当前运行；尚未验证新规则的真机效果。

## 与键盘一致的动作

| 命令 | 字段 | 行为 |
|---|---|---|
| move | `xyz_mm: [x,y,z]` | 底盘坐标毫米增量；+X前、+Y左、+Z上；从上一命令目标累加，朝向不变 |
| head | `head_deg: [yaw,pitch]` | 头部绝对角度，单位度，对应 h |
| gripper | `key: "c"` 或 `"o"` | 闭合/打开，对应同名键 |
| stop | 独立停止接口 | 停止会话，不自动撤回 |

### 双视角定位、无进展复核与动作决策（默认 localized）

当前记录使用 `pressb-conversation-v5`、`pressb-localization-v3` 和 `pressb-localized-progress-v3`，并记录 `execution_policy=yz_alignment_before_forward`、`forward_guard_policy=wrist_tip_overlap`，新增 `forward_guard_format=pressb-wrist-tip-overlap-v1`。旧v2坐标记录和v4门控记录仍可读，保留原始含义，不改写旧日志。

定位工具显式输出坐标单位：默认 `coordinate_units=normalized_1000`（整幅图的0～1000坐标，也接受明确声明的 `normalized_01`）；程序统一除以相应尺度，保存为0～1归一化坐标，再计算像素偏差。图像原点左上，向右和向下为正。`coordinate_conversion` 保存输入单位、除数和换算来源；原始返回仍完整归档。单位缺失、混合或越界时，不依据数值猜单位，不裁剪坐标，相关位置保留null并记录解析原因。模型输入只使用规范化视图，不混入未经换算的原始坐标。

每个相机独立计算 `dx=按钮框中心.x−指端.x`、`dy=按钮框中心.y−指端.y`，提供归一化、像素与按钮宽高单位偏差。部分按钮框的中心只是可见部分框中心，不冒充完整按钮中心；图像偏差不直接映射为机器人XYZ或毫米，也不证明三维接触对齐。缺失位置不补旧值。定位请求仍为当前双图、qwen38、temperature=0、thinking关闭、512输出token、120秒超时。

连续同轴同向动作达到3次，且没有明确投影改善或无法比较时，程序触发只读假设复核。连续正X前推达到3次也会触发接触假设复核，即使二维投影偏差看似减小，因为它不能证明指端接触或按钮触发。首次复核使用触发动作段起始与当前双视角共4张图；后续复核可从上次预期的观测开始比较。请求中的 `commands_between_images` 包含两端画面之间全部实际命令；最近3次同向动作窗口只用于判断是否触发，不冒充两图之间的完整执行历史。复核同时接收规范化偏差；明确区分“按钮可见”“已经对齐”和“只差距离”。它输出观察到的效果、“仅距离不足”假设是否有证据、其他解释及下一步应核对的变化，所有结论仍标记为模型判断。触发条件是重新检查的依据，不是按压成功或失败判定。

复核完成后必须重新进行动作决策。该轮原始工具响应附带与本轮观测和复核ID绑定的 `reassessment`，说明接受复核还是提出具体图像反证，并必须给出 `expected_visual_change`（执行后应出现的视觉变化）和 `if_no_change`（没有变化时应重新考虑的假设）。后续重复异常触发复核时，模型须用 `prediction_check=met/not_met/unknown` 检查上次预期是否实际出现；首轮没有历史预期则明确为 `not_supplied`。这不把模型的预期当成已经发生的事实。程序在执行前核对绑定；SDK仍只收到原有XYZ、头部或夹爪参数，不自动裁剪、反向或撤回。复核和动作请求期间均可停止，迟到响应不能执行。深度无效、单边手指按压和双图定位中的未知不会禁用全部动作；正X仍须通过独立腕图重叠检查，独立检查未知则不放行。复核用于防止不经核对反复沿用同一个假设。

完成仍须看到本次目标按钮亮起及后续撤回证据，模型完成报告与现场人工结论分开保存。命令完成只表示发送完成，不表示实测到位、接触或成功。共享执行器、HTTP动作结构、单动作在途和命令去重保持不变。

每轮 `localization/` 保存请求、原始响应、规范化坐标、图片哈希和耗时，`localized_progress.json` 保存前后数值；触发信息单独保存在 `hypothesis_review/trigger.json`。触发复核时，`hypothesis_review/` 保存 `trigger.json`、请求响应、`assessment.json`、`metrics.json` 及错误；动作归档保存对复核的响应。网页显示“无进展假设复核中”、两端观测ID、复核结论、定位／复核／动作各自的token和耗时。定位框只叠在对应保存快照上；旧v2越界坐标明确提示单位异常，不画到画布外。持续历史及64K压缩规则继续使用，程序触发与模型判断均保留证据来源。

原一键启动方式不变。本次仅运行代码检查与保存画面的模型回放，不自动接管机器人；额外复核会增加触发轮次的推理耗时。

### 旧当前偏差短闭环（显式 grounded）

显式使用 `--decision-mode grounded` 时：当前双图独立判读 → 短记忆中的动作决策 → 原共享执行器 → 新观测和偏差复核。模型保持关闭thinking。该模式默认动作请求包含3张成功步骤拼图＋当前双图，共5张；旧的过程图片和长段“已对齐”理由不逐轮累积。完整模型请求、响应、动作和观测继续归档。

当前判读只看2张原图，使用 `localization.py` 的 `locate_alignment` 工具：模型定位头图中目标按钮可按压面的框和选定手指可见前端，并报告两视角可见性、腕图局部关系及当前灯态。按钮框与指尖坐标均为整张原图中的0～1归一化坐标，原点左上，图像向右为+x、向下为+y。找不到的框／点保持null，不补出被裁掉的指尖。

`pressb-grounding-v2` 由程序根据“按钮中心减指尖”计算横向／高度关系，避免模型同时自由描述坐标和上下关系。横向偏差除以按钮框宽度、纵向偏差除以框高度，分别显示为多少个按钮宽度／高度，并给出小／中／大档位。这些数值依赖模型定位，只是图像投影偏差，**不是毫米误差、像素到机器人位移的标定，也不证明三维接触对齐**。框或点未知时，相关关系和大小也保持unknown。头图与腕图中的手指身份不能直接等同；图像右侧也不能直接当作机器人右侧。动作决策消费绑定当前观测的判读及原图，已执行命令和新观测用于检验调整后的变化。默认仍为2张判读图、5张动作图。

默认以**头图右侧手指**按压。该手指看不清时，当前判读保持unknown，右指偏好不被覆盖为左指。面板、按钮或接触手指在头图中看不全时，提示Agent优先调整头部获得完整视野；成功示范中的绝对pitch约+30°作为低头参考，实际角度随当前构图调整。已有视野合适时可保持当前角度，不注入固定启动低头动作，也不把30°当作每轮增量或角度门槛。

每轮 `control_policy.py` 生成绑定当前观测的 `control_plan.json`，把下一步的目的明确写为阶段建议：

| 阶段 | 要解决的问题 |
|---|---|
| `get_view` | 获得能定位目标按钮和所选指尖的视角；结合实测头姿与上一绝对目标选择新的合适视角 |
| `align` | 优先处理图像偏差较大的主轴，检查实际动作后的变化，而非无依据地重复微调 |
| `recheck` | 定位偏差明显反向或恶化时，重新核对定位、实际命令和视角，不立即机械反向或加大步长 |
| `approach` | 明确选择接近／按压，结合当前双视角与独立腕图横向检查评估前推 |
| `withdraw` | 已有本次亮灯证据，选择撤回并获取后续视觉证据 |
| `complete` | 引用本次亮灯与之后撤回的观测ID报告完成 |

`align` 的主轴是 `focus`，按当前误差档位提供5／10／20 mm试探步长建议；模型仍可依据当前画面和反馈选择其他数值。这些建议不是标定补偿、最小位移、执行限幅或必须执行的动作。程序不会因此裁剪、拆分或改写XYZ。前后定位只在手指参考一致、实测头姿基本稳定、按钮框尺寸可比且确有手部运动记录时比较；不能可靠比较时明确写未知，不将类别不变等同于没有进展。

在 `get_view` 阶段，如果视野仍不够、实测头姿相对上次目标记录基本未变（两轴差值均不超过1°），却再次请求完全相同的绝对头部目标，程序拒绝该候选并让模型继续修正，选择不同的合理头姿或重新观察；修正不设次数上限，网络请求失败或人工停止仍结束会话。重复发送 `[0,30]` 不会被解释成再低头30°。头部转动只改变头图构图，不移动手部或腕相机。

亮灯和撤回证据保存在本次运行记忆中，始终标明模型判断，与现场人工结论分开。若当前已亮而此前单帧灯态不确定，按需用前后四图核验亮灯变化；必要的撤回确认也独立使用前后双视角共4张图。这些调用只读模型，不执行运动。命令发送完成不等于已经撤离，单张亮灯图或历史案例不证明本次触发。

grounded使用`pressb-conversation-v3`。动作模型增加`visual_basis`与`expected_effect`决策字段；通过当前判读一致性检查后去除这两个字段，原数值不变地交给现有HTTP动作接口。声明 `reduce_horizontal_error` 必须Y非零，`reduce_vertical_error` 必须Z非零，`reduce_both_errors` 必须Y、Z均非零；这三种纠偏目的都要求X=0，不能以“纠偏”名义隐藏前推。明确选择 `approach`／`press` 并说明当前依据仍允许前推，**额外视觉放行条件仍只有当前腕图横向位于两指之间**，不新增头图对齐、高度或深度有效性门槛。阶段建议本身不构成额外执行门槛。新手部移动会使旧撤回满足状态失效；完成必须引用本次亮灯与之后撤回的观测ID。

当前版本还将同一判读明确写成双向关系，例如“按钮在手指上方，即手指在按钮下方”。`control_memory.json` 中的 `alignment_control` 记录每个偏差连续出现的观测数、期间实际Y/Z命令及方向往返，提示优先检查长期未处理的偏差。计数不表示像素误差没有改善，轴上有命令也不等于已经纠正；头姿改变、换指或判读未知会中断比较。网页的“运行记忆”中可查看这些记录。版本记录为 `pressb-alignment-control-v1`。

针对本装置直立面板的通常头部视角，提示词将“手指低于按钮→考虑抬高+Z”作为定性初始判断，允许根据当前画面或已执行动作的效果提出反证；这不是像素到机器人坐标标定，也不是固定补偿。校验器检查明确的主宾颠倒和动作语义/参数矛盾，例如判读按钮在上方却写按钮在下方、理由说抬高却发负Z。同一动作列表明确说 `move forward, robot-right and lower` 时也检查X、Y、Z符号，不能省掉所说的右移Y。嵌套宾语和代词指代不明时不强行反推主宾关系；否定、过去动作和 `then` 后的下一步不当成本轮动作。不合法的候选持续修正，不设次数上限；拒绝的候选不会执行，网络请求失败或人工停止仍结束本轮实验。否定句“未清楚看到按钮”不会当成“看到按钮”。语言校验覆盖明确句式，不能证明视觉或运动策略正确；模型仍须用实际新画面检验假设。

网页分别显示模型定位、按按钮宽／高计的偏差、策略阶段、主轴、建议步长和动作后变化。定位及策略均标明对应观测ID、模型来源与非毫米标定含义，不叠加到可能已经变化的实时视频。`perception/assessment.json` 保存v2定位和派生关系；`control_plan.json` 保存策略、几何比较和头部目标信息。旧v1判读仍可查看，失败案例读取器同时支持v1／v2并检查观测绑定；策略建议不计为执行动作或人工确认。

### 默认 localized：先Y/Z对齐，再允许正X

每个 `X>0` 移动候选（包括XYZ联动）都必须通过检查；同一观测首次出现正X候选时，程序发起一次独立只读请求，只输入绑定当前观测的腕部原图。同一观测的后续候选可复用该判读，但逐条校验候选参数；换观测后必须重做判读。该请求定位目标按钮可按区域框和箭头所指**物理指端**；程序按规范化坐标检查指端点是否同时落入按钮框的横向与纵向范围。箭头贴纸本身的尖端不自动当作物理接触点。按钮或指端不能完整辨认、坐标未知、点在框外，均不放行。

不满足时整条候选被拒绝，原共享执行器不会收到该动作；动作模型收到失败依据后重新选择Y/Z调整、改善取景、后撤或结束。偏差明显且方向有依据时先作较大的Y/Z调整，接近目标后再微调，避免把所有修正都拆成很小步。此处不预设毫米补偿量，也不改变模型动作。通过时原始XYZ原样发送，**不设正X步长上限**，不裁剪、不抽取Y/Z分量、不自动撤回。纯Y/Z及负X后撤不受本条件限制。

放行只适用于当前观测和当前候选，不沿用此前图像的结论。头图与测距继续供动作模型参考，但不参与此硬条件；无效深度不单独禁止前推。二维点入框不证明三维接触、实际触发或任务完成。仍要求本次亮灯与后续撤回证据。

网页分别显示腕图二维检查、所绑定观测、点入框计算、放行/拒绝、图片数、token及耗时。`forward_guard/` 保存请求、响应、规范化判读、`decision.json` 与各 `candidate-N.json`；候选拒绝不是动作执行，也不等于会话结束。检查本身增加一次串行腕图模型调用；停止和迟到响应保护保持有效。

### 历史对照模式的前推条件（不适用于默认 localized）

以下是2026-11-02早先增加的规则，仅在显式选择grounded、separated、direct旧模式时保留用于对照；当前默认localized已撤销该规则：**任何 `X>0` 的移动（包括同时改变Y/Z的动作），发送前必须确认当前腕图的按钮中心横向位于两指可见前端之间。** 按钮或任一指尖看不清、位置不确定、明确在区间之外均不放行。内侧边界允许单边手指按压，不强制闭爪。

按用户明确选择，**只检查腕图横向，不增加头图或高度条件**。按钮仍高于/低于手指时也可能通过；该条件不证明右指能接触按钮面，也不证明触发。无效深度、尚未亮灯不会单独阻止前推，但腕图横向条件必须通过。

候选动作为正X时，程序额外调用一次独立只读检查，仅输入该观测的1张原始腕图和目标，不输入案例、旧结论、深度或待执行动作。三个输出是按钮可见、两指前端可见、按钮横向位于两指之间；均明确yes才放行。该调用使用同一qwen38服务、关闭thinking，增加一次推理开销。每次新观测都重新判断，不沿用上一轮通过状态。

不满足时整条候选命令不发送，也不自动删掉X、改数值或替模型补动作；模型可持续修正，重新选择非前推的移动、转头、夹爪、观察或合法报告无法继续。同一观测尚未放行时，重复的正X候选持续拒绝而不执行；修正不设次数上限。检查本身输出非法时同样持续修正，网络请求失败或人工停止仍结束。零X、负X和非移动命令不触发此检查。Agent在实际提交HTTP前再次检查放行记录与观测ID及完整XYZ是否匹配；键盘、共享执行器、插值及HTTP命令格式保持原有语义。

网页显示“前推条件检查中”“前推未放行/正X已放行”，对应观测、判断、独立图片数、token及耗时。每轮 `forward_guard/` 保存请求、响应、判读、候选动作、放行结果、错误与metrics；`task.json` 记录 `forward_guard_policy=wrist_horizontal`。旧日志继续正常显示。部署打包已包含整个 `src/pressb`，新模块随现有包部署。

### 原持续会话模式（separated／direct）

`--decision-mode separated` 保留此前流程：获取观测 → 独立判读 → 持续会话中的动作决策 → 原共享执行器。`--decision-mode direct` 保留直接动作决策，两个入口均支持。separated两阶段共用 qwen38 服务，增加一次串行推理，不承诺提速；不会改变底层命令、插值或完成语义。

判读首轮仅输入当前头部／腕部2张图，之后输入上一轮与当前4张图、必要视角状态和期间实际执行的命令。它不看案例、历史理由、旧判读或待执行动作，只输出按钮可见性、图像框、手指关系、灯态、前后变化及未知项，不输出XYZ或下一步动作。重新观察明确标记期间没有运动。图像右侧不能直接等同机器人右侧，固定测距点不是按钮或指尖标定点。

独立判读以 `INDEPENDENT_PERCEPTION_MODEL_ASSESSMENT` 消息追加到动作上下文，绑定观测ID；原图仍给动作模型核对，不伪造tool回执。判读是模型估计，动作模型若不同意需引用当前画面反证或重新观察。允许单边按压、无效深度或未确认触发时依据画面前推；正X须通过上文新增的独立腕图横向条件检查。单张亮灯图不能独立证明本次触发，后撤命令也不能独立证明完成撤回。

两阶段均关闭thinking、最多512输出token、120秒请求超时；各自格式修正不设次数上限，网络请求失败不自动绕过该阶段。判读／修正／压缩／动作请求均可停止，迟到响应不执行。分离模式日志使用 `pressb-conversation-v2`，直接模式为v1，机器人HTTP schema不变。失败案例加载兼容旧记录和判读阶段中断的未执行轮次。

网页分别显示判读、前后变化、动作理由、观测ID、两阶段图片数与token／耗时；实时视频不一定等于决策快照，需以观测ID为准。每轮 `perception/` 保存独立请求、原始响应、修正、`assessment.json`、`metrics.json` 和错误。动作请求仍在原路径，`action_metrics.json` 汇总动作请求及全部修正的耗时和token。响应按 `response-0.json`、`response-1.json` …持续编号归档；网页按数字选择最新响应，显示当前修正阶段、累计请求次数和最近拒绝原因。动作修正保存 `correction.json`，只读判读等阶段保存对应的 `validation-N.json`；产生合法动作或判读后显示已通过，停止后保留全部记录。

`--demo` 直接读取原始键盘 `session.json` 和 `operations/*/operation.json`。每步一张前后双视角拼图，上方before、下方after，左head、右wrist；附带原始命令、深度和缺失信息。成功来源单独记录为用户确认，原始final缺失保持原样。

以下持续历史及压缩规则适用于localized/separated/direct：一次任务维护一个持续会话，开头提供任务、配置、精简成功/失败文字。按一键入口的旧模式默认值，全部14张案例图加入当前双图后首轮共16张；显式使用 `--demo-last-steps` 或关闭失败案例时按实际数量统计。后续逐轮追加原始 assistant 工具调用、对应 tool 执行结果和新的双视角 user 消息，不再重建最近5轮摘要。旧模式默认未压缩时第N轮有 `14+2N` 张图（第15轮44张）。Chat Completions HTTP仍提交有效历史，通过稳定前缀利用服务缓存，不是服务端只接收增量。图片预编码复用，不丢图降级。

成功案例完整归档保留全部11步，包括第11步中断和缺失after；是否全部输入模型由实际选择决定。加载失败案例时保留14条实际动作及原理由、前后深度/关键状态，第15轮中断不算动作。失败观察使用Fxx短引用，`observations`表保留原始观测ID；这不是本次LIVE ID。

模型只看决策所需数据：坐标、速度在开头给一次；实测与命令位姿严格区分，模型视图位置/深度转换为毫米保留0.1mm、四元数4位、角度0.1度。保留实测夹爪SDK原生值及其未知状态，不将夹爪命令当实测。哈希、设备序列号、原始时间戳、重复相机参数、手臂/躯干完整关节和力矩、插值轨迹只留完整日志。实际执行参数不舍入。约131mm软参考从成功复盘引用的亮灯边界读取；更换示范不沿用旧案例数值。

`--context-budget-tokens` 默认65536，两种入口均支持。首次调用 `/tokenize`，后续按实际usage和新增内容估算，接近预算再精确计数。超预算时保留固定案例、最近5个完整决策轮次及当前观测，并生成旧动作台账和一次只读模型摘要；摘要最多引用3个本次运行旧观测，保留它们的双视角。旧图标记为EARLIER，不冒充当前。摘要是模型判断，不是现场确认；非法格式或证据引用持续修正，不设次数上限；网络请求失败或压缩后仍超预算则停止并记录原因。不静默删除案例图片。模型请求/压缩期间均可停止，迟到响应不执行。

普通动作保持不启用thinking，最多512输出token，理由通常一句话，接近按压时仍交代视角、手指、偏差与目的。工具参数与机器人HTTP协议未改变。

最新失败案例的 `case_review.json` 和 `case_review.md` 记录现场反馈“没有对准、压在边缘”，以及头部图可见偏置、腕图遮挡、未执行横向精调和连续前推等证据。第7–14轮只改X、累计前推85 mm；最后3轮再前推15 mm，测距仅从约131.54变到130.99 mm，没有确认亮灯。模型多次写“之后重新检查对齐”，却未实际调整Y/Z。成功示范的横向-20 mm仅作比较，不变成固定补偿。分析区分用户反馈、图像/日志事实和推断，原始日志保持不变。旧失败案例 `20261101_174626_c319289f` 仍保留，需要时可通过 `--failure-case` 显式选择。localized/grounded默认不加载这些失败参考。

提示词要求接近/按压时用现有reason说明目标可见视角、实际接触手指、残余偏差和本次调整依据；目标丢失或重复前推没有新触发证据时重新评估。允许单边按压、无效深度下继续前推的规则不变，不新增执行器限制，也不强制下降50 mm。

历史验证：2026-11-01 使用旧成功示范 `20261101_165200_b34ebc84` 和保存的末态观测验证了15图请求，`qwen38` 在约35.9秒返回合法工具调用，报告89498个输入token。目录 `outputs/agent_context_validation_20261101_failure_v1_retry/` 保留完整请求、响应和结果（`replay_only`、执行命令数0）；这不是当前16图配置的模型验证。首次验证中断记录另保留在不带 `_retry` 的目录。

## HTTP 接口与兼容性

保留端口6210及 `/v2` 路由，session schema改为 `pressb-agent-keyboard-v1`。新版客户端拒绝旧session；新版服务拒绝旧平面/press参数。旧日志仍可查看，不自动重放。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/v2/session` | 命令契约、速度、坐标和会话ID |
| POST | `/v2/observations` | `{session_id,command_id}`；异步采集任务 |
| POST | `/v2/actions` | `{session_id,command_id,observation_id,type,...命令字段}` |
| GET | `/v2/tasks/{task_id}` | 执行、采集、保存结果 |
| GET | `/v2/state` | 当前状态、故障和实测状态 |
| GET | `/v2/observations/{observation_id}` | 不可变观测清单 |
| GET | `/v2/artifacts/{artifact_id}` | 清单登记的文件 |
| POST | `/v2/stop` | `{}`；停止并关闭会话 |

一个动作在途时拒绝新动作；相同command_id与相同参数返回原任务，不重复运动。动作必须引用最新观测。HTTP202是接受任务，不表示完成。服务重启标记旧未完成日志为interrupted，不继续执行。已有 `--replay` 可用于Agent观测目录，只调用模型、不连接机器人；它不是现场实验的前置要求。
