# 右腕指端固定像素标定

日期：2026-11-03。人工在相机网页（`scripts/s1b_camera_view.py`，指端点模式）中标记，保存为 `right_wrist_fingertip_point.json`；闭合、张开各一个点，同目录 `*_closed.jpg` / `*_open.jpg` 是保存时的右腕原图（核对用）。

| 状态 | 像素 (640×360) | 归一化 | 用途 |
|---|---|---|---|
| 闭合 | (343, 248) | [0.5368, 0.6908] | **唯一对准／接触基准** |
| 张开 | (465, 286) | [0.7277, 0.7967] | 仅记录，不作对准基准 |

标记依据：右腕相机刚性安装，夹爪状态固定时物理指端在腕图中位置不变。张开点落在带白箭头的右指前端；该点与此前助手目视估计的指端约 (470,280) 一致。标定为人工标记，不是三维接触标定；夹爪或相机被碰动后必须重新标记。

## 为什么对准基准恒为闭合点

闭合夹爪只移动手指，不移动相机、面板或按钮。张开时把按钮对到闭合点 (343,248)，闭爪后按钮仍在原像素，而合拢的末端恰好移到该像素，前推即命中。若反过来用张开点 (465,286) 当基准，闭爪瞬间接触面跳到 (343,248)，按钮相对末端偏约 122 px（横向）和 38 px（纵向），相当于 1.5–2.6 个实测按钮框宽，且此时腕图已被合拢末端遮挡，无法再对准。

同一个像素因此承担两个角色，且天然统一：

- **对准／接触基准**：恒为 (343,248)，与夹爪状态无关，用于 Y/Z 方向表、腕图重叠检查和按压。
- **测距窗口**：也是 (343,248)。张开时在此冻结按钮深度 `z_b`（需按钮框覆盖该点、在闭合带内）。

## 闭爪后的按压：实时深度闭环

2026-11-04 实测（`outputs/agent_web/20261104_181642_4bcda3a5`）：闭爪后该像素仍有约 20 个有效深度点，读数随前推近似 1:1 下降（228 → 210 → 195 → 180 → 169 mm），说明合拢末端并没有填满测距窗口。因此闭爪后按每轮实时深度闭环：

- 终点：实时读数到 `150 − 过压量` mm（默认过压 5 mm，即 145 mm；`--press-overpress-mm` 可调）。150 mm 是闭爪按下按钮时的实测读数。
- 每轮可前推量 = min(实时读数 − 145 mm，冻结上限 `z_b − 145 mm − 闭爪后已前推净量`)，并受 `--press-max-travel-mm` 硬上限约束。
- 实时读数只对产生它的那次观测有效；不可信（无深度、有效像素不足、测距点偏离、读数 < 130 mm 等）时只用冻结上限，并在记录中标明 `bound`。
- 实时读数只能让行程更短：同一实验里机械臂被挡住、深度停在 161 mm 时，冻结上限仍会阻止继续加推。

`--fingertip-state` 只作记录：程序需要知道当前是在冻结阶段还是实时闭环阶段，但它绝不改变对准点。

## 使用

```bash
.conda/envs/pressb/bin/python scripts/s1b_agent_run.py \
  --fingertip-calibration docs/astribot/planar_control/fingertip_calibration/right_wrist_fingertip_point.json \
  --fingertip-state open
```

一键启动器在服务就绪后，会把相机测距点切到该闭合点并确认生效，然后才启动 Agent；只对本次运行生效，不改写机器人上保存的测距点。切换失败则不运行。一键启动默认不加载示范，需要时用 `--demo <键盘会话目录>` 显式加入。

启用后：腕图的接触端由程序使用该固定点（闭合点）提供，模型只定位按钮；`dx/dy`、腕图正 X 重叠检查均用此点。头图的指端仍由模型定位。执行 `c/o` 后程序只更新记录的夹爪状态，对准点不变。校准文件必须包含 `closed` 点，缺少时启动即报错，即使以 `open` 启动也一样。标定来源、路径与 sha256 记录在 `agent/task.json` 的 `fingertip_calibration`，每轮定位记录含 `tip_source`（含 `aim_state`、`gripper_state`、`marked_states`）。不加该参数时行为与之前完全一致。
